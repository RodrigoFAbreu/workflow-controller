## Goal

Close [#116](https://github.com/RodrigoFAbreu/workflow-controller/issues/116), the three gaps the C10c reviews left in `controller/functional_review.py`:

1. A bold line after a blank line that opens a non-flow section (`**Setup** for this flow: ...`, `**Setup: none needed.**`) or a qualified flow header (`**Then, 2. Run it again.**`) ends the flow before it, and the text after it is read by no flow: the tester never sees it and no round says so.
2. A qualified flow header without the comma (`**Optional K. Title.**`) or with a qualifier of more than one word does not end the previous flow, so an optional flow is folded into the required one above it.
3. `_linked_path` refuses every link that starts with `../`, so a checklist in `docs/ACTIVE_MILESTONE.md` that links `../tests/checklist.md` (a file inside the repository, one folder up from `docs/`) ends at `checklist_unrecognised`, although `candidate_flows.read_file` already joins the link to the checklist's folder and refuses a result outside the repository.

The roadmap row adds one point from the trial run of `prepare-functional-review` on Haiku: the Controller needs the section heading to match exactly. The recogniser already matches `Functional review checklist` at any level and in any case; what the trial lacked is a refusal that says so. D5 covers it.

## Decisions

Each decision states one principle.

- **D1. A flow header may carry a qualifier, and it starts a flow.** A bold line `**<qualifier> <label><marker> ...**` is a flow start of the bold shape when the qualifier is one or two words of letters followed by a comma (`**Optional, K. Title.**`, `**Optional extra, K. Title.**`, `**Then, 2. Run it again.**`), or one word of the closed list `QUALIFIERS` (`Optional`, `Required`, `Extra`, `Additional`, `Conditional`) with no comma (`**Optional K. Title.**`). The label is a `LABEL_RULE` label, and the marker is exactly the plain bold shape's (`[.):]` not followed by a digit, `_BOLD_RE`), so `**Optional K.** Title`, `**Optional, K.** Title` and `**Optional K: Title.**` start a flow as `**K.** Title` does. The closed list matches in any case, in `_BOLD_RE` and in `_SECTION_END_RE` alike (`**optional K. Title.**` is a flow start in both, so the line is neither folded into the flow above nor dropped). The qualified label goes through the same candidate check as a plain one: `**Optional, 123. Title.**`, whose label breaks the rule, is refused as partly recognised, as `**123. no.**` is. The label is the one after the qualifier; the text runs, like any bold flow, to the next flow start, heading or section-opening line, so it ends the flow before it. The comma form is bounded to two words because a comma before a label is not prose in a flow header, and the bound limits the prose it can mistake (`**If it fails, a. Retry it.**`, three words, stays in its flow; `**Then check, 2. It prints.**` is read as flow `2`, a recorded risk of the bound, and no checklist of the history holds one). The comma-less form is closed because `**Check step 2. It prints the version.**` and `**Verify exit code 0. Output is empty.**` are expectation lines of a flow and must stay inside it (an existing test pins them). `**Optional extra K. Title.**` (several words, no comma) is outside the closed list on purpose and stays in the flow above; the guide says so. A qualified header that is an optional flow is a flow: the tester runs it as it runs any other, and the checklist author already marks it optional in its own text. The roadmap's "optional" meaning is not modelled. Because the bold shape is tried first, a qualified line now makes it decide in a document whose flows are headings, a table or a numbered list: `### A. One` / `run` / `**Then, 2. Run it again.**` / `### B. Two` is refused by the cross-shape check as a plain `**2. x**` in a heading flow already is, and `1. a` / `2. b` / `**Optional, K. Extra.** y` or a table with the same line changes from silently dropping the line to a refusal. That is kept and stated (D4 lists it among the allowed differences).
- **D2. Text the bold shape would leave in no flow is refused.** Once the bold shape has decided, the lines between two consecutive flow spans (the end of one flow to the start of the next) belong to no flow. A gap holding any non-blank line is refused with the existing `checklist_unrecognised` stop, naming the first such line (its first 60 characters), the flow before it and the flow after it, and saying to put the text inside the flow it belongs to or move the section to the end. The only lines a gap may hold are a heading line and a `**Flows...**` bold line that carries no text after its closing `**` (the usual lone `**Flows:**` introducer); any text under them is a gap line of its own and is refused. The check is on the gap, not on the regions the section words open, so it covers every way a flow ends: a section-opening bold line (`**Setup** for this flow: ...`, `**Setup: none needed.**`, `**Known limitations**`), a `**Flows:** text` line and a heading with text under it (`### Notes for A`). Text before the first flow (the usual `Setup`) and after the last flow (the usual `Known limitations`) is not between two flows and is read as before. The evidence gains `interior`, a list of `{line, before, after}` (at most 20) and still carries `recognised`, so the refusal opens as one about a checklist whose flows were read (`_unrecognised` takes its lead from `evidence["recognised"]`). The refusal applies to the bold shape only; the heading shape ends a flow at a heading, and the table and numbered shapes do not end a flow at a bold line. A bold line inside a heading flow is flow text of that shape, except a qualified or numbered one that makes the bold shape decide (D1).
- **D3. Link containment is decided once, after the join.** `_linked_path` keeps refusing what cannot be a repository path (an absolute path, `~`, a URL, a backslash, a NUL, an empty target) and no longer refuses a normalised target that starts with `../`: such a link resolves from the checklist's own folder, and the reader decides. `read_flows` documents `read_file(path)` as taking that path relative to the checklist's folder and returning `None` for a missing file or a result outside the repository; `candidate_flows.read_file` already does this (`controller/functional_review.py`, the join and the `..` test). The refusal for a link that leaves the repository stays `checklist_unrecognised`, and its message now says a link resolves from the checklist's own folder and must stay inside the repository. No second containment test is added to `read_flows`.
- **D4. Real checklists decide whether the rules are too strict.** Before the change is accepted the committed checklist sections of the repository's history (every `Functional review checklist` section of `docs/ACTIVE_MILESTONE.md` in `git log`, as FL2 measured them) are read on the base commit and on the change: no checklist read before is refused or read differently except through D1 (an `Optional, K.` flow is now a flow, and a qualified bold line in a document of another shape now makes the bold shape decide and is refused by the cross-shape check, or read where it was dropped) and D2 (text in a gap between two flows). The corpus is widened as FL2 measured it: the history of `docs/ACTIVE_MILESTONE.md`, the completed milestone narratives, the fixtures and the Manager's checklists. The measured numbers go in the checkpoint report and the pull request (`docs/ACTIVE_MILESTONE.md` is not a CP1 file). A checklist that D2 newly refuses is a finding to decide, not to hide: the rule narrows to the shape that was dropped.
- **D5. A missing section names the heading it needs.** When the section is missing, the refusal's reason names the heading to write (`Functional review checklist`, at any heading level, in any case) and lists up to five headings of the document that contain both `functional` and `checklist` (or `review` and `checklist`) without being that heading, with their line numbers, so a heading such as `Functional-review checklist (round 2)` is seen as the near miss it is. The match itself is unchanged: widening it would let a checklist with a different title decide a round.
- **D6. The documentation follows the change.** `docs/guide/automation.md` (the recognised shapes and regions, `:430-460`) states the qualified header and its exclusions (`**Optional extra K. Title.**` stays in the flow above), the gap refusal and the link rule, and tells an operator that an optional flow now runs and can stop a round that used to pass over it; `docs/common-problems.md` (the `checklist_unrecognised` line) names the two new cases; the roadmap marks C10j done.

## Out of scope

Modelling `optional` (skipping an optional flow that cannot run), changing the heading match, reading a link that points outside the repository, and any change to the table, heading or numbered shapes beyond what D1 and D2 state.
