## Goal

Close three open `review-follow-up` issues in full: [#103](https://github.com/RodrigoFAbreu/workflow-controller/issues/103) (`controller/prices.json` ships empty, so a Codex job's cost is always `unknown`), [#104](https://github.com/RodrigoFAbreu/workflow-controller/issues/104) (four small points of the usage record) and [#108](https://github.com/RodrigoFAbreu/workflow-controller/issues/108) (`settings show` prints the stored round caps, not the ones a run uses, and the fallback cap stop says "the external count"). Nothing reads cost figures for a decision yet (A3 will), and no run stops wrongly today; these are the figures and the words an operator reads. No new setting, option, exit code or gate.

## Decisions

Each decision states one principle.

- **D1. A price is taken from the provider's page on the day it is entered (#103).** `controller/prices.json` gets the API list prices of every model the Controller launches by default: `gpt-6.1-sol` (OpenAI), `claude-opus-5-5`, `claude-sonnet-5-5` and `claude-haiku-5-5` (Anthropic). The implementer reads each provider's published API pricing page at the time (WebFetch), enters the per-token prices of the four priced groups (`input`, `cache_read`, `cache_write`, `output`), and records the page URLs in `source` and the day read in `date`. `version` becomes 2 (`docs/guide/development.md`, "Maintaining the price table": a new version, never an edit of history). No price is typed from memory: when a page cannot be read, or a price it lists cannot be read unambiguously, that model is left out of the table and the checkpoint stops and reports it, because a wrong price is worse than the honest `unknown`. A group the provider does not charge for is not a missing price: it is entered as `0`, and the `source` text says so. OpenAI lists input, cached input and output prices but no cache-write price, and every recorded Codex rollout reports `cache_write_input_tokens: 0`, so `gpt-6.1-sol` is entered with `cache_write: 0` (`cost_of` needs a numeric price for all four groups, and leaving the model out would keep #103's defect).  Claude's cache write is priced at the provider's five-minute write rate, and the `source` text says so (the table has one write price per model). A model that the harness lists but the Controller never launches by default (`claude-fable-5-1` and the short aliases `opus`, `sonnet`, `haiku`) stays out: an alias names no fixed model, so its cost stays `unknown`.
- **D2. A default model without a price fails a test (#103).** One test collects every model id the Controller launches by default (`routing.DEFAULT_MODEL` and the models of the built-in routes, `review.DEFAULT_MODEL`, `review.CLAUDE_DEFAULT_MODEL`, `claude_build.PROBE_MODEL`) and requires a complete price for each in the shipped table; it fails when a new default model is added without one. The collection reads the module values, not a copy of the ids, so the test follows the code.
- **D3. A cost is labelled for what it is (#103).** The guides say "API list-price equivalent" wherever they show a cost figure from the table or from `total_cost_usd`: on a subscription it is not what the user pays. `docs/guide/how-it-works.md` ("The usage record") loses the sentence that the table ships with no prices. The pages that show a cost figure are `docs/guide/commands.md` (the `status` cost, the `telemetry` totals), `docs/guide/workers.md` (the session cost, the usage record's cost) and `docs/guide/runtime.md` (a Claude review's cost totals); CP1 owns the label on all of them, so no page is left to chance.
- **D4. Partly reported reasoning is `unknown`, as in telemetry (#104, point 1).** `usage_record.reasoning_tokens` returns `None` when any result lacks `thinking_tokens`, not the subtotal of those that carry it, so the record's reasoning figure is `unknown` and never an incomplete sum flagged `reported`. This is `worker_stream.session_telemetry`'s rule for a partly missing figure. A mixed-presence converter test pins it, with an all-present and an all-absent case beside it.
- **D5. `wall_ms` is documented per job kind, not aligned (#104, point 2).** The sources measure different things, and aligning them would change a figure for no consumer. A Claude worker's is the harness-reported `duration_ms` summed over its `result` events. A Codex worker's is the Controller's own elapsed monotonic time around `run_bounded` (`controller/codex_worker.py:201-204`), passed into the record as `wall_ms` (`controller/codex_worker_job.py:42`), so it is kept even when the run has no result events. A review's is `launched_at` to the terminal write, at whole-second resolution. The existing measurements are preserved. `docs/guide/workers.md` ("The usage record") and `docs/guide/how-it-works.md` name the source per kind and the resolution; the `UsageRecord` docstring says the same.
- **D6. The Mapping guard covers both reads (#104, point 3).** In `from_codex_rollouts` the `subagent` read uses the same `isinstance(rollout, Mapping)` guard as the `usage` read, so a malformed rollout is skipped and not an `AttributeError`.
- **D7. A retried Codex review is tested end to end (#104, point 4).** One test drives the real `launch_review` retry with the fake Codex and requires `out["usage_rollouts"]` to count the first root rollout once, and a sub-agent rollout once.
- **D8. `settings show` prints the round caps in force and where each comes from (#108, point 1).** The stored rows are unchanged (a stored `null` stays `null (default)`). After the three `review.*round_cap` rows, `settings show` prints one line per cap in force: `review.local_round_cap in force = 6 (built-in)`, with the origin one of `built-in`, `its own setting or option` or `deprecated review.round_cap`, computed by one function, `cli._round_caps_in_force`, that returns each cap with its origin (the `deprecated_given` rule is derived once, there), and `cli._round_caps` is built from it, so the value and the origin cannot differ. `settings show` can only show the origins a settings file and the built-in defaults give; the command-line origin appears for a run's own settings and is covered by the unit test, and the docs say so. The deprecated `review.round_cap` row carries `(deprecated: use the local and external caps)`. With `--json`, `values` and `sources` are unchanged and a new key `round_caps_in_force` holds `{"local": {"cap": N, "origin": ...}, "external": {...}}`; a consumer of the old keys is unaffected.
- **D9. The cap stop says "round N" (#108, point 2).** `job._cap_gate` words the count as "{stage} review round N has reached the {fired} round cap of C" for the single fallback number and the Controller's job count, and for a split count as "{stage} review {fired} round N has reached the {fired} round cap of C" (the `where` text already names both the local and the external round, so the wording says which one N is), not "the {fired} count N". The text around it is unchanged, including the three ways on.
- **D10. The documentation and the issues follow the change.** `docs/guide/commands.md` (`settings show`), `docs/guide/runtime.md` (the settings table and the round caps) and `docs/common-problems.md` ("A run stopped at the review round cap", which accounts for "the count and the cap") describe D8 and D9 (`docs/guide/troubleshooting.md` does not quote the stop and is not changed); `docs/ROADMAP.md` marks CU3c done and drops the follow-ups for #103, #104 and #108; `docs/ACTIVE_MILESTONE.md` is updated at acceptance. The release note, the release history row and the compatibility line belong to the docs pull request after the 1.27.5 release, as for every earlier release. The pull request closes #103, #104 and #108.
