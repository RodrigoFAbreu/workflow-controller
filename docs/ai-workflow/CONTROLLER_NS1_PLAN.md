## Goal

A test or a worker command that sends `kill(-1, SIGKILL)` (or `killpg(1, ...)`) must reach only the test run, never the desktop session (the crashes of 2026-11-09; PR #328 fixed the Controller's own signalling, not a test's). One mechanism: where the Controller's test commands run. `tools/run_tests.py`, the documented entry point for every test selection (`python3 -m unittest` names are accepted as selection names), starts each namespace-safe shard inside `unshare --user --map-current-user --pid --fork --kill-child --mount-proc`, so a signal to every process reaches only that namespace. **Revision 3 (plan amendment, owner decision of 2026-11-14):** a wrapped full run fails about 35 tests in more than nine modules, so this item ships the wrapper, the kill proof and a recorded list of the modules that are not namespace-safe, and runs a shard that holds one of them unwrapped with a notice; making the whole suite namespace-clean is a follow-up backlog item (D9). **Owner-visible scope fact (review round 3, I1):** the planner spreads a module's atoms over several shards (on this host 138 of 148 modules span more than one of the 8 shards of a default local run), so with more than nine listed modules a full or `--serial` local run wraps no shard at all, and `--namespace require` cannot run the full suite until the follow-up lands. The protection of this item reaches a narrow selection (a test file, a module, a fast loop: the case a worker runs), not the full suite.

## What exists

- `tools/run_tests.py` `run_shards` starts each shard as `python3 tools/run_tests.py exec-shard ...` through `subprocess.Popen(..., start_new_session=True)` and, after the shard exits, finds leftovers by the `run_id/shard` marker (`ts.scan_marked_processes`, which reads `/proc/*/environ` of the host) and kills them. CI runs `exec-shard` directly and does not use `run_shards`.
- Verified on this host (util-linux 2.42.4): `unshare --user --map-current-user --pid --fork --mount-proc sh -c 'id -u; kill -9 -1'` keeps uid 1000, mounts `/proc` for the namespace, and `kill -1` finds no process. `--map-current-user` (not `-r`) keeps the invoking uid, so a root-in-namespace write to an unwritable test root (the artifact in the issue, `tests.test_runtime.EnsureRuntimeRootTest.test_unwritable_root_is_a_named_refusal`) is not introduced. The remaining artifact is that the namespace's init is the first child, which does not reap orphaned zombies (`tests.test_review.FakeLaunchTest.test_a_hung_review_is_killed_at_the_deadline_with_its_descendants`).
- `controller.runtime.signalable_group` already refuses group 1 for the Controller's own signals (PR #328). It is out of scope.

## Decisions

- **D1. One wrapper, in the runner.** `run_shards` builds the shard command through one function that prefixes the namespace launcher. The probe (`unshare ... true`, bounded, once per run) decides whether the host allows unprivileged user namespaces. The probe runs the builder's own argv with a trivial command (every D1 flag, including `--kill-child` and `--map-current-user`, which need util-linux 2.32 and 2.38), so an older `unshare` that lacks one flag fails the probe and falls back or refuses by D2; it never fails a shard.
- **D2. Strictness is one setting with three values** (`--namespace auto|require|off`, default from `CONTROLLER_TEST_NAMESPACE`, else `auto`): `auto` wraps when the probe succeeds and otherwise runs unwrapped and prints one notice naming the probe's reason; `require` refuses a run when the probe fails (exit via the runner's usage error); `off` never wraps. **Owner decision O1 (flagged, not finalized here): the default.** This plan recommends `auto` (a host without user namespaces, for example a hardened runner, can still run the suite) and ships `require` for anyone who wants the refusal.
- **D3. CI is unchanged.** CI calls `exec-shard` directly, on disposable runners, and stays inside its time budget. Only `run_shards` (local runs, `--serial` included) wraps, and only a shard with no namespace-unsafe module (D9).
- **D4. Namespace artifacts are read from evidence, and fixed by the follow-up.** CP2 reads a wrapped full run once and records which modules fail because of the namespace. The fixes (a zombie-aware liveness check in the test, not a reaper in the runner, because a blanket `waitpid(-1)` would steal the runner's own children) are not made here (D9). A failure the namespace does not cause is not touched.
- **D5. Not in this item.** A refusal of a bare `python3 -m unittest` for Controller workers (the "refuse unwrapped" half) needs a per-repository disallow rule, since `routing.worker_disallowed_tools` is shared by every managed repository; and the guard harness that makes `os.kill` refuse pid 1 or lower. Both stay open as the owner's second decision in the item page (O2), and the docs tell workers to use `tools/run_tests.py`.

- **D6. Ctrl-C on a wrapped shard is a direct SIGKILL of its group (review round 1, I1).** The executor is PID 1 of the namespace, and a signal from outside the namespace to its init is dropped unless the init has a handler (`pid_namespaces(7)`; reproduced: SIGTERM to a wrapped `unshare` group left it running, only SIGKILL ended it). `exec-shard` has a SIGTERM handler only while a conformance lane runs (`_stop_lane_on_signals`), so the graceful path would wait the whole `INTERRUPT_GRACE_SECONDS` and end in SIGKILL anyway. Decision: `exec-shard` is **not** changed. For a wrapped shard `run_shards` sends SIGKILL to the shard's process group on interrupt, with no grace wait; SIGKILL of `unshare` ends the executor through `--kill-child`, and the kernel kills every other process of the namespace when its init dies, so nothing outlives it. The lane's graceful `lane.stop()` does not run on that path, which is acceptable because nothing can outlive the namespace. An unwrapped shard (`off`, the `auto` fallback) keeps the SIGTERM-then-SIGKILL path unchanged.
- **D7. The post-exit leak scan is weaker under the wrapper, by design (review round 1, I3).** When the namespace init exits, the kernel kills every other process of the namespace, so `finish()`'s `scan_marked_processes` finds nothing after a wrapped shard exits: a process that left the group, started after the executor's own scan, or survived a killed executor is killed silently instead of being reported and failing the shard. Accepted: locally the cleanup is stronger and the leak signal weaker, and CI (unwrapped) keeps the full signal and is where a leak fails a run. The executor's own in-namespace scan still runs and still reports. The guide page records this in ADR 0005's terms. The scan itself is unchanged and still works while a shard runs (host `/proc` reads the environ of a process in a child user namespace of the same user), which is what CP1 tests.
- **D8. A third namespace artifact: the lock probe answers `unknown` outside the init PID namespace (review round 1, I2).** `controller/lock.py` (lines 288 and 336) answers `unknown`, never `free`, when the reader is not in the init PID namespace, deliberately, because `/proc/locks` hides an entry whose taker cannot be seen. Every wrapped local run is outside the init namespace, so: `tests/test_scenario_kit.py` `KillPointTest` (asserts `lock-after-kill == "free"`, line 305; the scenario sandbox does not unshare PID, so its probe runs in the shard's namespace) needs to become namespace-aware, expecting `free` in the init namespace and `unknown` elsewhere (via `controller.lock.read_pid_namespace`); that is the follow-up's change (D9); the `skipUnless(_INIT_NS, ...)` tests in `tests/test_observe.py` and the `unknown` branches in `tests/test_cli.py` and `tests/test_lock.py` already adapt and stay. Coverage shift, recorded on the guide page: a wrapped shard would skip the init-namespace `free` tests (`tests/test_observe.py:751` is `skipUnless(_INIT_NS, ...)`: wrapped, it skips instead of failing), so the modules holding them are listed as namespace-unsafe like the modules that fail, and run unwrapped (D9) until the follow-up lands; CI, which is unwrapped, runs them. The scenario kit's own nested `unshare --user --map-root-user` inside the shard's user namespace is read by CP2's wrapped run. Under revision 3 the `KillPointTest` change, like every other test-side fix, belongs to the follow-up (D9), not to this item; the module is recorded as namespace-unsafe.
- **D9. Split: wrap only namespace-safe shards (amendment 0, revision 3).** CP2's wrapped full run showed that the namespace breaks about 35 tests in more than nine modules beyond the files revision 2 listed (the lock probe's `unknown` outside the init PID namespace, `/proc` and zombie assumptions, one golden). The owner chose to ship one small releasable mechanism. (a) `tools/test_shards.py` holds `NAMESPACE_UNSAFE_MODULES`, a tuple of test module names derived from that run, each with a one-line reason; a module is listed when the namespace makes one of its tests fail **or skip** (review round 3, I2), found by comparing the failures and the skips of the wrapped full run with those of an unwrapped full run; (b) `run_shards` wraps a shard only when none of its atoms' modules is in the tuple (a module is resolved from the atom key by matching it against each listed module name or its `name + "."` prefix, without an inventory, because `--replay` has none before the run and building one costs a full discovery that can raise `InventoryError` for a plan recorded before a rename; review round 3, O1), and runs the others unwrapped, with one notice naming the modules and the count of unwrapped shards; the run header reads `namespace: isolated` when every shard is wrapped, else `namespace: isolated for N of M shards (unwrapped: <modules>)`; (c) `require` refuses a run that selects any such shard, naming the modules, because `require` means never unwrapped; `off` is unchanged; (d) a selection with no unsafe module (a single test file, a fast loop) is fully wrapped, which is the case that matters for a worker running one test; a full or `--serial` local run is **not** wrapped (review round 3, I1, option (b): the per-shard rule is kept and its consequence is stated rather than adding planner shards for the unsafe atoms, which would change the planner for a debt the follow-up removes), and the run header says so (`namespace: isolated for 0 of 8 shards (unwrapped: ...)`); the Goal, R1 and CP3 say the same; (e) the follow-up item makes the suite namespace-clean and empties the tuple, so the tuple is a bounded, visible debt; until it lands no listed module can be run wrapped through the runner (`auto` runs it bare and `require` refuses; review round 3, O2: no override is added), so the follow-up removes an entry, with its fix, before it can verify that module wrapped; the item is added to the backlog by a separate documentation change, not by this item's commits. A shard that holds an unsafe module and a safe one runs unwrapped as a whole; shards are not split.

### CP1: the namespace wrapper and its strictness setting

Add the probe, the argv builder and the `--namespace` option (with `CONTROLLER_TEST_NAMESPACE`) to the runner, and route `run_shards` through the builder; `exec-shard` itself is unchanged. A second test pins D7: a marked process left in a wrapped shard is gone after the shard exits and the post-exit scan reports nothing.
