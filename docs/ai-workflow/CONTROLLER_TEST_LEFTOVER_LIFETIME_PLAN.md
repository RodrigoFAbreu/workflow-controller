## Goal

A review worker that runs the full suite inside a Controller-launched job can be killed mid-test (a tool timeout, a `SIGKILL`). The tests' own cleanups then never run, and `tests/fake_claude.py` and the stdin anchor of the `Controller` the test started stay alive for ever. Because the worker's test process was a child of the real job's worker, the real Controller adopts both as owned processes, and the job sits in `DRAINING` for up to the three-hour `worker.drain_detach_seconds` bound. It happened on 2026-10-02 (C4, 3 h), 2026-10-08 (D1, 30 min), 2026-10-09 (3 h, exit 45), 2026-10-10 (C9d, 34 s) and 2026-10-10 (C8, about 2 h), each time ended by hand.

**Reproduced on this branch's base (2026-10-11).** `timeout -s KILL 4 python3 -m unittest tests.test_resume.SettleWindowLossTest.test_a_wrong_match_whose_real_fire_follows_the_re_attach_fails_closed` leaves exactly the two processes the incidents named, with the fake's working directory under `/tmp/controller-lifecycle-*/settle-wrong-match/`: a `tests/fake_claude.py -p --input-format stream-json …` and a `python3 -I -c "The worker's stdin anchor…"`, both children of the Controller that ran the command. (The anchor's own working directory is `/`, `_spawn_anchor()` in `controller/worker.py`, so a replay finds anchors through the job record's recorded anchor identity and the ownership tag, never through a working directory; review R3-O1.) The same test run to the end leaves nothing. So the defect is not one test's cleanup; any test that starts a fake worker leaks it when the test process is killed. Review round 3 showed that the fake is not the only leftover: a killed test can also leave a detached `--orphan-burst` helper blocked on an absent gate, a separate-session `fake-claude-daemon` with a 3,600-second `sleep`, a gated `setsid` descendant blocked on its FIFO, and a child Controller (`_CHILD_STEP`) whose own worker never ends. Review round 4 added the sleepers the tests themselves start in a new session or behind a leader that exits with the test (`process_fixtures.spawn_sleeper`, the `member` mode, `test_lock`'s bystanders, `test_worker`'s leader-with-member and `_sleeper(new_session=True)`), each a 3,600-second `sleep` that inherits the real job's ownership tag. Each keeps the real job draining (the anchor ends only when no tagged process remains), so each is bounded here.

**Why they never end.** The fake waits for stdin end-of-file, and the anchor holds the write end of that pipe. The anchor ends itself only when its worker is gone (and no tagged process and no supervisor remains), after 60 s. Each waits for the other: nothing ends either until something outside does. A real `claude` has the same shape, which is deliberate (a worker survives a lost Controller until `resume` re-attaches), so the production rule is right; the *fake* has no notion of "my supervisor is gone for good".

After this milestone a fake worker whose parent has died ends itself, and takes its own process group with it, after a bounded orphan lifetime (default 300 s); the anchor then ends by its own existing rule 60 s later. A killed test run therefore stops holding a real job within about six minutes, down from up to three hours, with no change to the Controller; the detached helper and daemon shapes (D6, D10) within about eleven minutes (two 300 s bounds, or one 600 s lifetime, plus the anchor's 60 s), every test-started sleeper within the same eleven (D12: a numeric bound of 600 s, not "finite"), and a child Controller that a test started (D14) within about sixteen (its 600 s deadline, the 300 s of the fake it supervised, then the anchor's 60 s; review R9-O1). That the real job's drain then ends is inferred (the anchor's rule plus `controller.anchor.worker_gone` counting a zombie as gone), not observed: D7's replay runs in a plain shell, not under a Controller-launched worker (review LR1-006).

1. `tests/fake_claude.py` starts an orphan watchdog in `main()` and announces, through a readiness file, when it is armed.
2. The watchdog is pinned by contract tests, including the exact shape of the incident (the stdin write end held by a separate process); every orphaning test waits for readiness first.
3. The fake's detached helpers, daemons and subprocess sleepers are bounded (D6, D10, D12), the child Controllers that tests start end when their test dies (D9, D11), and every other process a test starts that can outlive it has a lifetime of at most 600 s or a parent guard (D12).
4. The development guide, the roadmap and follow-up 8 say what is fixed and what stays in C12.

Out of scope: everything under `controller/` (no recogniser for test directories, no shorter drain bound; see D4), the stdin anchor and its 60 s rule, `worker.drain_detach_seconds`, the other C12 items (a message from another session, network retries), a release.

## Decisions

- **D1. The watchdog lives in the fake, not in the tests' cleanups.** A cleanup cannot run when the test process is `SIGKILL`led; a process that watches its own parent can. So every test that starts the fake (`tests/test_worker.py`'s `_SupervisedCase`, the lifecycle, usage and e2e suites, and `tests/test_resume.py`'s `_LostControllerCase` for the fake itself) is covered with no edit to any of them, and so is any future one. The exceptions are the processes that are not the fake or that leave the fake's reach: D6 and D10 (detached helpers and daemons, which a group kill cannot reach) and D9 and D11 (child Controllers, which are not fakes).
- **D2. Orphaned means "my original parent is gone".** `main()` records `os.getppid()` at start. A watchdog with **no thread** polls every 0.5 s: `signal.setitimer(signal.ITIMER_REAL, 0.5, 0.5)` with a `SIGALRM` handler that checks `os.getppid()` (blocking `readline()`/`sleep()` are retried after the handler, PEP 475). A thread is rejected because `_fork_descendant()` (`FAKE_CLAUDE_DESCENDANT` modes) calls `os.fork()`, and from Python 3.12 a fork in a multi-threaded process prints a `DeprecationWarning` into the worker's stderr (review LR1-002); the streaming session's stdin reader thread (`tests/fake_claude.py`, `_stream_session`) is not a counter-example, because the streaming path never calls `os.fork()` (`step_orphan_burst` uses `subprocess`), so "the fake has no threads" is not a property a later reader may rely on; the interval timer is not inherited by a forked child, and `subprocess` children (the `sleep` of hang mode) start without it. Once `os.getppid()` differs from the recorded value (the parent died and the process was re-parented to init or to a subreaper), the fake counts down `FAKE_CLAUDE_ORPHAN_SECONDS` (default `300`; `0` or a negative value disables the watchdog). When it expires the fake ends its process group with `SIGKILL` when it leads one (`os.getpgrp() == os.getpid()`, which `controller.worker.launch` guarantees by starting the worker in its own session), and otherwise only itself. A parent that dies between `fork` and the first line of `main()` makes the recorded "original" parent the adopter, so the watchdog never fires; the window is a few milliseconds and accepted (LR1-005). Nothing is written, no result line is emitted: a `SIGKILL` is the honest picture of a harness that was reaped. **Readiness (review R3-3):** once the timer is armed and the original parent recorded, the fake writes its pid to the path in `FAKE_CLAUDE_ORPHAN_READY_FILE` when that variable is set (written to a temporary name and renamed, so a reader never sees a partial file). A test that orphans a fake on purpose waits for that file before it kills the parent, so it can never hit the startup window above; the file is test plumbing, absent from every production path.
- **D3. 300 s, not shorter.** The lost-Controller tests deliberately orphan a fake and re-attach with `resume` within their own 60 s timeouts (`lose_controller`, `DrainDetachedReattachTest`). 300 s leaves five times that margin, while the whole leak is over in about six minutes (300 s plus the anchor's 60 s and one 5 s poll) instead of three hours. The knob exists so a future test that needs longer can say so, and so the contract tests can run it at 1 s.
- **D4. No Controller change; the Controller-side half stays in C12.** The roadmap also asked to "consider naming known test leftovers sooner than the drain bound". The Controller would have to recognise test directories (`/tmp/controller-lifecycle-*`) in production code, which couples it to its own test layout, and a real worker's leftovers look the same as a test's. The Controller-side recovery for leftovers it cannot tell apart (end by exact pid, or stop counting them) is C12's item (11.10) and keeps its scope; this milestone removes the source of the incidents instead. The user may overrule this at plan review.
- **D5. The group kill spares the anchor.** The anchor runs in its own session (`controller.worker.launch`), so the fake's `killpg` cannot reach it; the anchor ends by its own rule once the fake is gone. This milestone does not touch the anchor, so its production behaviour is byte-identical.
- **D6. The detached `--orphan-burst` helper is bounded (review R3-1).** `fake_claude.py --orphan-burst` returns before the watchdog starts (the burst is its whole job), and `step_orphan_burst` with `detach` starts it in a separate session with `--after-parent <fake pid>`, so the fake's group kill cannot reach it. Its descendants have finite `sleep` lifetimes, but the helper itself waits for the `gate` file without end (`orphan_burst()`, `while gate and not os.path.exists(gate)`), before it produces any descendant. A test killed before it creates the gate therefore leaves the helper alive, and the anchor's rule (no tagged process) waits for it. The gate wait now gives up after `FAKE_CLAUDE_ORPHAN_SECONDS` (default 300; `0` or negative: unbounded, as D2), counted from the moment the `--after-parent` wait ended (that wait is bounded by the fake's own watchdog), and the helper then exits having produced nothing. The helper that is released in time behaves as before. Bound for this shape: the fake's 300 s, the helper's 300 s, the anchor's 60 s.
- **D7. Verification is the incident, replayed, with every process shown to exist first (review R3-3, R3-O1).** Besides the unit-level contract tests, CP3 replays the killed run with the new code and `FAKE_CLAUDE_ORPHAN_SECONDS=2` in the environment, with `FAKE_CLAUDE_ORPHAN_READY_FILE` set to a fresh path. The replay driver is a plain shell session (not a Controller-launched worker; see the Goal). Each replay kills the **test process only, by pid** (`kill -KILL <pid>`, never its group: a tool timeout reaches the process, and the strict case is the one that leaves the children alive). Anchors are found through the job record's recorded anchor identity (`pid` and `start_ticks`) under the test's runtime directory, and the fake through the record's `worker_process` and the readiness file; a zombie counts as gone (`/proc/<pid>/stat` state `Z`). Before the kill the driver asserts that the fake (ready file present, process alive), the anchor and, in the second replay, the child Controller (the marker's pid) are all alive; a process that never existed cannot make the absence checks pass. The driver's cleanup is D16's. **The kill must be the driver's, not the test's (review R5-1):** where the test itself kills its child Controller shortly after the hold point (`lose_controller` polls every 20 ms, `_orphan_worker` after its 1 s line), the driver first holds the test (replay 2: `SIGSTOP`) or lands inside a window of seconds (replay 3), and treats "the child Controller was alive at the driver's kill" as a precondition: if it was not, the replay is invalid and is rerun or replaced by the race-free CP3 test, never reported as a pass.
  - **After the loss.** `tests.test_resume.SettleWindowLossTest.test_a_wrong_match_whose_real_fire_follows_the_re_attach_fails_closed` (it loses its own child Controller with `lose_controller` and never configures a hang point): the driver waits until the ready file exists and the fake's parent is no longer the child Controller it was started by (its ppid, read while that Controller was alive, is gone or has changed), then kills the test. Expected: no fake within 10 s, no anchor within 90 s. (`FAKE_CLAUDE_ORPHAN_SECONDS=2` is exported to the whole test, so the orphaned fake may end during the test's own `resume` before the driver's kill; a test failure from that is the replay's setup, not a defect, and the absence checks are unaffected.)
  - **Before the loss, at a real hang point (review R5-1).** `tests.test_resume.SettleWindowLossTest.test_a_persisted_settlement_is_load_bearing` (it sets `hang_after_state: ENDING`, so the child Controller writes the `controller-stopped` marker and sits in `hang()`). `hang()` is a hold point for the child Controller only: the marker is written and `lose_controller` (`ready()` polled every 20 ms, `process_fixtures.wait_until`) then `SIGKILL`s the child at once, so a driver that merely waits for the marker loses the race and the test's own kill, not `_PARENT_GUARD`, would end the child. The driver therefore **holds the test**: it polls for the fake's ready file (present long before the marker, which appears only after the turns have played and the state reaches `ENDING`), sends `SIGSTOP` to the test process the moment it exists, and checks that the marker is still absent (a precondition: if the marker already exists, the test may already have killed the child, so the replay is invalid and is rerun). A stopped test cannot kill its child and still dies to `SIGKILL`. The driver then waits for the marker (no timeout fallback: if it never appears the replay fails as a replay, not as a pass), asserts the child Controller (the marker's pid) and the fake alive, and kills the test by pid (`kill -KILL <pid>`, which ends a stopped process). Expected: the child Controller ends within 10 s (D9), the fake is then orphaned and ends within a further 10 s, no anchor within 90 s. CP3 test 12 covers the same guard without a stopped process, from a disposable driver.
  - **Child Controller blocked on a worker (`_CHILD_STEP`), at a real hold point (review R4-2).** `tests.test_resume.OrphanWorkerTest.test_the_kill_waits_for_a_delayed_worker_spawned_line` (`_CHILD_STEP_SLOW_SPAWN_LINE`: the child Controller has already recorded `worker_process`, writes its marker file and then sleeps 1 s before the `worker_spawned` append; the test's own `SIGKILL` of the child (`_OrphanWorkerCase._orphan_worker`, `tests/test_resume.py`) lands only after that second). The driver waits for the marker file (no timeout fallback) and for the ready file, finds the child Controller as the test process's only direct child whose command line carries the test's runtime root (read from `/proc`), asserts the child Controller and the fake alive, and kills the test by pid inside that second. **A precondition, not an assumption:** if the child Controller is not alive at the kill (the test's own kill won the race, or the ready file was absent when the marker appeared) the replay is invalid and is rerun, never reported as a pass. Expected: the child Controller ends within 10 s (D11), the fake within a further 10 s, no anchor within 90 s. CP3 test 13 covers the same guard without the race, from a disposable driver.
- **D8. No change in `controller/`, `tools/` or the CI.** The milestone changes `tests/fake_claude.py`, `tests/test_fake_claude_contract.py`, `tests/test_resume.py` (D9, D11), the test files that pin the daemon's `3600` (D10), `tests/process_fixtures.py`, `tests/test_lock.py` and `tests/test_worker.py` (D12), the fake's own subprocess sleepers (D12), two documentation pages and the roadmap. `python3 tools/check_docs.py` and the full suite must be green.
- **D9. The lost-Controller child ends when its test dies (LR1-001).** `_LOST_CONTROLLER`'s `hang()` (`tests/test_resume.py`) sleeps for ever until `lose_controller` sends `SIGKILL`; a test killed before that leaves the child Controller alive, which keeps the fake's original parent alive and so disarms D2. It uses the parent guard of D11: it calls `cli.main`, but with a pinned identity (D11), so it cannot re-exec.
- **D10. Separate-session leftovers other than the burst helper are bounded (review R3-1).** (a) The `daemon` mode of `bash_bg` leaves a `setsid` `sleep` that defaults to 3,600 s (`tests/fake_claude.py`, `_bash_command`), which `OwnershipTest.test_an_unrecognised_daemon_detaches_after_the_drain_bound_and_ends_nothing` (and the recognised-daemon tests) leave behind when their cleanup does not run. The default becomes the module constant `DAEMON_LIFETIME_SECONDS = 600`, and every test that pins `3600` for a daemon (`tests/test_worker.py`, `tests/test_job.py`, `tests/test_resume.py`; found by `grep -n 3600 tests/`, each match classified in CP2) refers to the constant instead; a test that needs a different life passes `orphan_seconds`. No test runs a daemon for 600 s. (b) The `orphan_gate` variant of the `setsid` orphan blocks on a FIFO until a writer opens it; the wait is wrapped as `timeout --foreground <N> bash -c 'read _ < gate'` (N = `FAKE_CLAUDE_ORPHAN_SECONDS`, default 300, with the same `0` rule: no `timeout`), then the descendant continues into its own finite `orphan_seconds`; the descendant keeps its pid (the `$!` the test records). `--foreground` is load-bearing (review R4-O1): without it GNU `timeout` calls `setpgid(0, 0)` and moves the wait into a new process group, which the fake's group kill (D2) then cannot reach and which would outlive the fake by up to N, lengthening this shape's leftover. Before its `setsid` the escapee is a background subshell of the fake's non-interactive `bash` (no job control), so it is in the fake's group and D2's `killpg` already ends it whenever the fake leads its group (always, under `controller.worker.launch`); the wrapper only matters for a fake that does not lead its group, and the audit table records that reasoning. The change adds `timeout` to the owned-process scans in `tests/test_worker.py`'s gated-escapee tests (`:2531` onward); CP2 test 9 asserts no `timeout` process outlives the fake, and those scans are re-run. (c) CP2 audits every other detached spawn in `tests/fake_claude.py` and the tests that start one (`setsid`, `start_new_session`, double forks, `FAKE_CLAUDE_DESCENDANT` modes) and records, for each, its bound in the plan's audit table in the checkpoint's self-review: finite by its own parameter (the descendant modes' `seconds`, the `setsid`/`reparent` orphan's `orphan_seconds`, default 60), bounded by this decision, or fixed. Bound for the daemon shape: 600 s plus the anchor's 60 s. The fake's two subprocess `sleep 3600`s are bounded by D12.
- **D11. Child Controllers end when their test dies, and nothing changes while it lives (review R3-2).** Tests start child Controllers as `python3 -c <script>`: `_LOST_CONTROLLER` (`_LostControllerCase.child`) and `_CHILD_STEP` (`_OrphanWorkerCase._orphan_worker`, with an unbounded worker timeout and a fake that waits for a release file the test's cleanup creates). A test killed before it kills the child leaves the Controller supervising its fake for ever, which disarms D2 (the fake's parent is alive). Both scripts get one shared prefix, `_PARENT_GUARD`, that records `os.getppid()` and arms `signal.setitimer(signal.ITIMER_REAL, 1, 1)` with a handler that calls `os._exit(0)` as soon as the parent differs (no thread, no change to `controller/`; the Controller uses no `SIGALRM`, and a handler that returns leaves blocking calls to be retried, PEP 475). While the test process lives the handler does nothing, so the scripts behave as before. The fake it leaves is then orphaned and D2 applies. **The rule is by whether the child can re-exec, not by how it is started or whether it calls `cli.main` (review R7-O1, round 7):** `cli.main` re-execs only for an *unpinned* identity (`controller/cli.py:2201`, `ident.source_kind == identity.SOURCE_KIND_UNPINNED and not read_only`, before `_reexec` at `:2220`; the `os.execve` is at `:178`). An interval timer survives `exec` but a Python signal handler does not, so a `SIGALRM` handler in a process that re-execs would let the default action terminate a live Controller (review R6-2, reproduced by the reviewer); that is the only hazard, and it is the routing criterion. **A `-c` script that replaces `identity.pin` and `identity.current` with a pinned `ControllerIdentity` before it calls `cli.main` can never reach `_reexec`, and takes this guard. A child that resolves its own identity (`-m controller`, or any script that does not pin) takes D14.** The guard's scripts are therefore: `_LOST_CONTROLLER` (`:2604`; it calls `cli.main` at `:2647` but patches `identity.pin`/`identity.current` with `unittest.mock.patch.object` first), `_CHILD_STEP` (`tests/test_resume.py`; `controller.job`/`execute_step`, no `cli`), `tests/test_lifecycle_orchestration.py`'s `_CHILD_STEP` (`:1198`), `_CHILD_WAITING_STEP` (`:2202`) and `_CHILD_CLI` (`:1737`, pinned by the same `patch.object`; started by `child_step` at `:1814`, whose cleanup `child.kill()` at `:1820` kills the Controller itself, so it needs no migration), and `tests/test_trunk_preflight.py`'s `_CHILD_CLI` (`:751`, `identity.pin = lambda: ident`; its `:930` cleanup and `:937` Ctrl-C test signal the Controller itself, so they need no migration and the twofold `SIGINT` forward of D14 does not apply to it) and `tests/test_cli.py`'s `_CHILD_RUN` (`:2052`, a pinned `-c` script, `identity.pin = lambda: ident; identity.current = lambda: ident`, then `cli.main`; started by `RunRecordCtrlCTest` at `:2072` as `run` with **no `--timeout`**, so its worker has no time limit and its fake waits on `FAKE_CLAUDE_HANG_UNTIL_FILE`, which only the fixture's cleanup creates, `_RunRecordFixture._end_workers`, `:1870-1874`; a test killed before its own `SIGINT` leaves a live Controller supervising a fake that never ends, so the fake's parent is alive and D2 never counts down; also started at `:2601` by `StepFollowTest` with `--timeout 30` under `subprocess.run(timeout=60)`, where the guard is harmless). `_CHILD_RUN`'s cleanup at `:2079` (`child.kill()`) kills the Controller itself and its Ctrl-C test signals the Controller directly (`child.send_signal(SIGINT)`), the same shape as `tests/test_trunk_preflight.py:937`, so it needs no migration; `RunRecordCtrlCTest` is a second check that a guarded child handles `SIGINT` once. **The list is a starting set, not a closed one (review R8-A):** these sites, and any Controller child that CP2's construct scan (test 11) finds, take this rule, so the next missed site is a classification decision in `LEFTOVER_INVENTORY`, not a plan defect. **The `-m` children are classified by what they do, not listed by file:** D14 takes every `-m controller` child that supervises a worker without a Controller `--timeout` (those of `tests/test_observation_equivalence.py` and `tests/test_packaged_runtime.py`). Every other `-m`/`-c` Controller child is a short read-only command (`status`, `follow`, `--version`; `tests/test_cli.py:232`, `:316`, `tests/test_identity.py:146`, `:259`, `:573`, `tests/test_version_authority.py:61`, `fixtures.run_controller_module` at `tests/fixtures.py:420`, and `tests/test_resume.py:2433` `_CHILD_ABANDON`, a short `job.abandon` call that self-terminates) or a `step`/`run` with `--timeout N`, N <= 600 (`tests/test_cli.py:2346`, `:2391` via `run_controller_module`, and `_CHILD_RUN` under `StepFollowTest`), and is recorded in `LEFTOVER_INVENTORY` as `bounded` with that reason. `_PARENT_GUARD` is a multi-line block (a handler `def`) that is prefixed to one-line, `;`-joined scripts, so the constant **ends with a newline** and is joined by plain string concatenation (`_PARENT_GUARD + _SCRIPT`), never by `;`, which would be a `SyntaxError`. - **D12. A numeric bound for every test-started leftover (review R4-1).** "Finite" is not an acceptance rule: a 3,600-second `sleep` is finite and keeps the real job draining for an hour. The rule is: **every process a test starts that a killed test can leave behind (it runs in a new session or group, or behind a leader that exits with the test, and it inherits the job's ownership tag) lives at most `LEFTOVER_LIFETIME_SECONDS = 600` or carries a parent guard (D11).** The constant lives in `tests/process_fixtures.py` so that a new long-lived helper inherits the bound instead of re-introducing `3600`. The scope is all of `tests/`, not the fake's spawns: `process_fixtures.py:88` (`spawn_sleeper`) and `:288` (`member` mode); `test_lock.py:94` (`_LEADER_WITH_BACKGROUND_MEMBER`), `:256`, `:392`, `:434`; `test_worker.py:1138` (`_LEADER_WITH_RUNNING_MEMBER`, whose leader exits at stdin end-of-file when the test dies), `:3333` (`_sleeper(new_session=True)`), `:3468`. These sleepers need seconds, so each is lowered to the constant; a test that needs longer passes its own value and says why. The subprocess Controllers that `tests/test_packaged_runtime.py` and `tests/test_observation_equivalence.py` (`:290`, `:299`) start (`python -m controller` supervising a fake) are `-m` child Controllers and take D14's independent deadline; they are **never** treated as bounded by the fake's watchdog, because a surviving Controller is the fake's live parent and so keeps the watchdog from ever counting down (review R6-2). A bound counts only if it is enforced by a process that outlives the test: a `timeout=` on `subprocess.run`/`communicate`, or any wait the test process performs itself, stops being enforced when the test is killed and is not a bound (D13). **The fake's own subprocess sleepers (review R5-2).** The fake starts two separate `sleep 3600` processes: the monitor's lifetime when a monitor has a `timeout` (`step_monitor`, `tests/fake_claude.py:1066`) and the hang-mode child (`FAKE_CLAUDE_HANG_CHILD_PID_FILE`, `:1356`). Both run in the fake's group, so D2's `killpg` reaches them only when the fake leads that group; several tests start the fake directly in the test runner's group (`tests/test_fake_claude_contract.py:624`, `:946`, and the monitor-timeout test at `:1010`), and there a killed test leaves the `sleep` for an hour behind a leader that is gone. ## Risks

- **A test that orphans a fake for longer than 300 s.** None exists today (the lost-Controller tests use 60 s timeouts); if one is added, the knob names the way out. The suite is the check: a re-attach test that exceeds the lifetime would fail loudly rather than flake, because the fake would be gone.
- **Re-parenting is not always to init.** In a Controller-launched run the adopter is the real Controller (a subreaper), in a container it may be pid 1 of the namespace; D2 compares against the recorded parent pid, never against `1`.
- **Killing a group.** `killpg` runs only when the fake leads its own group, so a fake started by a test directly (same group as the test process) is never allowed to take the test runner with it.
- **The anchor's 60 s.** D7 waits for it; if the anchor's rule ever changed the replay would show it.
- **The parent guard and signals.** `SIGALRM` interrupts a blocking call in the child Controller only to run a handler that returns; Python retries the call. The CP3 suite run (every `_LostControllerCase` and `_OrphanWorkerCase` test) is the check, and 14 pins that the guard does nothing while the parent lives.
- **The 600 s sleepers.** A test that sleeps a helper for the full 600 s is a defect the static check (11) flags; the sleepers D12 lists need seconds, so lowering them changes no test's outcome, and the full suite is the check. The residual: a killed run can still hold the real job for about eleven minutes (about sixteen when a `-m` or console-script child Controller supervised the fake, D14), which is the stated bound, not zero.
- **The daemon's 600 s.** A test that needs a daemon for longer passes `orphan_seconds`; the contract test 8 pins the default.
- **Artifact declaration.** The generator's default template classifies none of `controller/`, `tests/`, `tools/` or the `docs/*.md` pages (known follow-up 10). The declaration is the previous milestone's reviewed classification with this item's ids, so every path the checkpoints name is classified at both stages: `tests/` and `docs/guide/` are protected prefixes at the implementation stage, and `docs/ROADMAP.md` and `docs/ACTIVE_MILESTONE.md` are excluded by exact path at both stages. The exclusion of `docs/ROADMAP.md` is deliberate (review R3-O2): the template excludes the roadmap because other lanes and the workflow's own archival write it, and protecting it would stale this item's technical approval on every such write. Its content is held by requirement R6 (`check_docs.py`, the "agree" check) and read at the functional and pull-request review, not bound by the implementation digest. No checkpoint adds a path outside the classified set (`tests/process_fixtures.py` is under `tests/`).
