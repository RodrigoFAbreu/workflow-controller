# H4e3b: Codex worker, step 5e

Item id: `workflow-controller-h4e3b`.

Run the managed repository's generator (`scripts/prepare-ai-review.sh`) safely after the Controller lands a Codex worker's commits. This item needs H4e3. It was split from H4e3 on 2026-11-10 ([#334](https://github.com/RodrigoFAbreu/workflow-controller/issues/334)) by owner decision. Complexity: medium. **Status: implemented on its milestone branch, awaiting review.**

## Scope, one mechanism

What the Controller may execute after a landing, what it must compare first, and how it refuses the rest.

## What was built

Plan: `docs/ai-workflow/CONTROLLER_H4E3B_PLAN.md`, four checkpoints. After a Codex apply role's landing and carry out, the Controller runs the generator itself (`controller/generator_run.py`) after three checks: the landing touched nothing under `scripts/` or `.workflow-manager/`, `scripts/` is exactly the installed release's files, and every path the generator would copy resolves inside the repository. The generator runs with an interpreter configuration that loads nothing from the repository root, the user site, cached bytecode or the environment, and the tree and copy sources are checked again afterwards. A success is followed by a second `reconcile`; any refusal ends at H4e3's gate `carry_bundle_regeneration_pending`, now naming the cause. The run is recorded; `resume` runs it again from the start only for a run that was cut off, and a refusal (a `GATE_BLOCKED` job) is cleared and then regenerated by hand. The checks, the environment and each cause's remedy are on [harnesses](../guide/harnesses.md#what-the-controller-runs-after-a-landing) and [common problems](../common-problems.md#a-routed-apply-stopped-at-carry_bundle_regeneration_pending). The adversarial tests are `tests/test_generator_run.py` and `tests/test_codex_apply_regeneration.py`.

The landing check runs before the Controller's first protocol query after a landing, so a landed edit of a managed script (with its record digest edited to match) is refused before any query executes it; ordinary regression tests cover both the first run and `resume`.

## Inputs: the two findings

- **H4E3-R5-001 (plan round 5 of H4e3).** A worker can land a `scripts/sitecustomize.py`; the managed generator, run by the Controller right after the landing, imports it, so worker-written code runs with the Controller's authority.
- **H4E3-R6-001 (plan round 6 of H4e3).** The same class by other import-path routes: a module that shadows a standard-library module, and a forged `.pyc` that Python loads in place of its source. A name-status diff of the landing is the comparison that the design has to decide on, together with the import path and `.pyc` cases.

## Out of scope

The carry in and out and the recovery of the two apply roles (H4e3), `milestone-implement` (H4f).
