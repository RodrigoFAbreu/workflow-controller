| F-0d0b8c00b1f9 | implementation LOCAL_MODEL_IMPLEMENTATION_REVIEW round 1 | **O1. `_exec_cause` matches unreachable-model words as bare substrings of stderr that also echoes the probe command.** `controller/codex_verify.py:36-37,311-313` checks `_UNREACHABLE_WORDS` (including `"429"`, `"limit"`, `"login"`) with `in` against the last 2000 characters of stderr. `codex exec` streams its activity, including the commands it runs, to stderr, and the probe command carries a random TCP port, random hex markers and `mkdtemp` paths. Reproduced: a `RunResult(exit_code=1, stderr=b"...create_connection(('127.0.0.1',34291),3)...\nError: sandbox setup failed")` is classified `model_unreachable` (inconclusive, "run again") instead of `exec_failed`. Both refuse with exit 20 and nothing is recorded, so this does not affect safety. It only mislabels a refusal that D7 names separately. Suggested fix: match word-bounded tokens (or `review.LIMIT_ERRORS` names and an HTTP-status pattern), or read the structured `codex_error_info` via `review.scan_rollouts` as the plan review's O1 proposed. | follow-up | https://github.com/RodrigoFAbreu/workflow-controller/issues/217 |
