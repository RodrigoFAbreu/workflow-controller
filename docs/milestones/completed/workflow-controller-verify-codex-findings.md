| F-86337662bea8 | implementation LOCAL_MODEL_IMPLEMENTATION_REVIEW round 1 | **O1. The listing does not keep the package root and a dependency apart.** `_list_root` names the package root's entries with no label and a dependency's entries with `dep:<name>/`, and a line is `name\0flag\0value\n`, where a name may contain `\n` and a symlink target may contain `\n` too. So two different layouts can produce one listing. Measured on this branch: a package root that holds a directory literally named `dep:x/` (and no `x` found anywhere) and the same package with `x` hoisted to `lib/node_modules/x` give the identical digest `3608bd3d…`, although in the first the launcher falls back to its own `vendor/` and in the second it runs `x`. A symlink whose target text ends in `\n<name>` and a file named `<name>` can also swap. Only an actor that can write the install tree, which is outside the stated trust boundary, can arrange this, so it is optional. Giving the root its own label (for example `pkg/`) and length-prefixing or escaping each field would make the listing injective; `DIGEST_VERSION` would then change, which is safe because nothing has recorded a digest yet. | follow-up | https://github.com/RodrigoFAbreu/workflow-controller/issues/174#issuecomment-6470043940 |
