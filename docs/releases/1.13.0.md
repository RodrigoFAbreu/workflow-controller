# Workflow Controller 1.13.0

[Back to the documentation map](../README.md)

These notes describe the milestone `workflow-controller-review-modes` (ROADMAP C14), from its plan
(`docs/ai-workflow/CONTROLLER_REVIEW_MODES_PLAN.md`). They were written before the release; the
release itself is made from the pull request that carries this milestone.

## The owner chooses how the external review runs (1.13.0)

**A user with one provider is no longer blocked at an external review gate.** `review.mode`
(`auto`, `cross-model`, `single-provider`, `manual`; `--review-mode` on `step`, `run` and `explain`
for one command) chooses the reviewer at the two external review gates (rows 14 and 28).

| Mode | At an external review gate |
|---|---|
| `auto` (default) | the Codex reviewer when `reviewer.harness` is set; else a fresh Claude reviewer, only where `verify` reports the stage's `require` lowered; else the ordinary gate |
| `cross-model` | the reviewer of `reviewer.harness`; without a distinct provider, the `review_mode_unavailable` stop |
| `single-provider` | the Claude reviewer, only while the lowered-policy signal stands; else refused before launch |
| `manual` | the ordinary gate |

The same-provider reviewer is a second harness on the review-only seam: a fresh read-only Claude
session in a disposable copy, its boundary pinned by captures from `claude 2.1.296`. Its approval is
labelled lowered and recorded with `review.mode`, `review.mode_source` and `review.lowered`; the
Workflow still decides whether a verdict is acceptable. If it refuses for lack of a distinct model,
the job ends `INCOMPLETE` and the next step stops at `review_mode_unavailable` with the three ways
out (see [the problem entry](../common-problems.md#a-run-stopped-at-review_mode_unavailable)).

**What changes for an existing repository.** A repository that sets nothing and whose newest
gate-policy adoption lowered no `require` behaves exactly as under 1.12.0. **A repository whose newest
adoption lowered `distinct_reviewer_models` now has its external review run by the Controller under
`auto`**, with a Claude reviewer, instead of stopping at the gate. To keep the old stop, set
`review.mode` to `manual`. Under a human gate `auto` still goes to the gate.

## Also in this release

- `explain` prints the review mode, its source and what the next step does; with `--json` it gains a
  `review_mode` block, and no existing key changes.
- `telemetry` rows gain `review_mode` and `lowered`; `--by review_mode` groups by them. Records without
  the keys read `cross-model`.
- `scenario-review-mode-single-provider` drives all four modes through `cli.main`.

## Configuration

| setting | type | default | flag |
|---|---|---|---|
| `review.mode` | choice | `auto` | `--review-mode` |
| `reviewer.same_provider_model` | string or `null` | `claude-opus-5-5` | none |
| `reviewer.same_provider_effort` | string or `null` | `high` | none |

The settings file moves to table generation 8; the first 1.13.0 command that writes it adds the three
rows. An older Controller sharing it warns about the unknown keys, ignores them, and its
`settings clean` refuses.

## Known limitations

- The lowered-policy signal is read from the text of the Workflow's `gate_policy` check and stands only
  while the lowering adoption is the newest; without it `auto` returns to the gate and `single-provider`
  is refused. A structured field in a later Workflow release is the real fix.
- The Claude boundary is pinned to the measured Claude Code version; a different one stops the launch
  with the name of the check.

## Upgrading

Install 1.13.0 as you installed 1.12.0 (see the [update page](../update.md)). To keep a lane's reviews as
under 1.12.0, set `review.mode` to `manual`. **Downgrading:** 1.12.0 reads the job records 1.13.0 writes.
