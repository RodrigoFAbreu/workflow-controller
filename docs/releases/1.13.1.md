# Workflow Controller 1.13.1

[Back to the documentation map](../README.md)

These notes were written after the release from the archived narrative
(`docs/milestones/completed/workflow-controller-cleanup-1.md`) and the plan
(`docs/ai-workflow/CONTROLLER_CLEANUP_1_PLAN.md`). The milestone was `workflow-controller-cleanup-1`
(ROADMAP CU1), the first clean-up milestone, accepted on 2026-10-17 by gate policy. It was released
from pull request #77 (squash `f46999d`).

## Sixteen review follow-ups and known defects fixed (1.13.1)

**A patch release.** 1.13.1 works through the open issues labelled `review-follow-up` or `bug` that
the earlier milestones left behind: sixteen in all, and the pull request closed each of them. It adds
no setting, no command and no exit code. Most of the fixes are in the tests and the documentation;
five change what an operator can see, and they come first.

## What you may notice

- **A model alias for the Claude reviewer is refused before anything runs**
  ([#72](https://github.com/RodrigoFAbreu/workflow-controller/issues/72)). `reviewer.same_provider_model`
  must be a full model id: a name that begins `claude-` and holds only letters, digits, `.`, `_` and
  `-`, such as `claude-opus-5-5`. An alias such as `opus` is now refused with `ReviewLaunchRefused`
  (exit 30, `not_started: true`) before the reviewer is launched, so nothing is spent. Under 1.13.0
  the alias was refused only after the review had run and been paid for, because Claude reports the
  full id back and the Controller compares it exactly. A name of the right shape that resolves to
  another id (a `-latest` name, for example) still starts and is refused at the session's `init`
  event. See [the reviewer settings](../guide/runtime.md) and
  [the problem entry](../common-problems.md).
- **A Claude review's cost and tokens are kept and counted**
  ([#75](https://github.com/RodrigoFAbreu/workflow-controller/issues/75)). The job record of a
  same-provider review now keeps the cost and token totals its `result` events reported, in
  `review.telemetry`. A review runs at most two Claude sessions (the first attempt and the one retry),
  and their figures are added together. They are kept even when the `init` check refuses the run,
  because that run was already paid for. `telemetry` counts them, so `telemetry --by review_mode`
  shows the cost of the same-provider row. A Codex review still keeps no figures and shows as
  "telemetry unavailable". The `--json` rows gain no new key.
- **Recovery messages name the review's own harness**
  ([#74](https://github.com/RodrigoFAbreu/workflow-controller/issues/74)). When `resume` cannot end or
  verify a review's process group, its message, and the message of the record it reconciles, say
  Claude or Codex as the review was run; before, they always said Codex. The launch-refusal entry on
  [the common-problems page](../common-problems.md) now lists the Claude checks too.
- **The plan round cap works on work items the Workflow governs as `"1"`**
  ([#67](https://github.com/RodrigoFAbreu/workflow-controller/issues/67)). Such an item is reviewed
  at `AWAITING_EXTERNAL_PLAN_REVIEW`, a phase the Controller's round count did not look at, so its
  plan round stayed at 1 and the cap stopped it only when the cap was 1. The round is now counted at
  that phase.
- **`telemetry` works out review rounds in one pass**
  ([#63](https://github.com/RodrigoFAbreu/workflow-controller/issues/63)). The rounds of all jobs
  are counted in one oldest-first pass per repository and work item, with the same results as
  before. The time it took grew with the square of the number of job records; it now grows in line
  with it.

## Reliability of the tests

These change no behaviour; they make the test suite catch more and fail less by chance.

- **Two flaky worker tests are fixed**
  ([#62](https://github.com/RodrigoFAbreu/workflow-controller/issues/62)). The two timing-sensitive
  tests in `tests/test_worker.py` that failed on CI were reproduced on two CPUs with parallel copies
  (about 1 run in 40 and 1 in 20) and passed 60 such runs each after the fix.
- **The test-leftover guard sees more process starts**
  ([#56](https://github.com/RodrigoFAbreu/workflow-controller/issues/56)): a bare `check_call`,
  `check_output` or `run` imported from `subprocess`, a `timeout=` run whose command is not written
  out as a list, and a shell FIFO read. Four cleanups that killed a whole process group now end
  their process by pid.
- **The unmerged-index usage-limit test checks what its name says**
  ([#57](https://github.com/RodrigoFAbreu/workflow-controller/issues/57)): every stage of all seven
  unmerged statuses gets a blob that really changes, each run live and through `resume`.
- **A lost merge reply after a squash onto a moved trunk is tested**
  ([#58](https://github.com/RodrigoFAbreu/workflow-controller/issues/58)).
- **The review round cap is tested on a real Workflow 2.12.0 answer**
  ([#65](https://github.com/RodrigoFAbreu/workflow-controller/issues/65)). Workflow 2.12.0 is
  vendored for the tests under `tests/workflow_releases/2.12.0/`, and the release-iterating tests run
  against it as well. A new test checks that the cap gate and `telemetry` report the Workflow's own
  round ("given by the Workflow").
- **The Controller's copy of the plan-review ready phases is pinned**
  ([#66](https://github.com/RodrigoFAbreu/workflow-controller/issues/66)): a test compares it with
  the Controller's other copy and with the Workflow's own list, in this repository's installed
  Workflow and in each vendored release that defines it.
- **The Claude reviewer's containment probe is committed**
  ([#73](https://github.com/RodrigoFAbreu/workflow-controller/issues/73)). The 2026-10-17 probe of
  symlinks and paths outside the disposable copy is kept as a capture under
  `tests/harness_contract/claude/`; it found every outside read denied.

## Documentation and tidying

- **Which tests read the installed Workflow**
  ([#55](https://github.com/RodrigoFAbreu/workflow-controller/issues/55)). The
  [development guide](../guide/development.md#workflow-release-trees) now names the one exception to
  "the tests read only vendored trees": the review-round tests read this repository's installed
  `scripts/`.
- **No roadmap step ids on the task pages**
  ([#59](https://github.com/RodrigoFAbreu/workflow-controller/issues/59)). `tools/check_docs.py`
  rejects a step id such as a C-number on the user pages outside `docs/guide/`, and the ids it found
  were reworded. The guides are exempt.
- **The before-and-after `telemetry` steps are exact**
  ([#64](https://github.com/RodrigoFAbreu/workflow-controller/issues/64)). The
  [runtime guide](../guide/runtime.md) says how to get the "before" figures (the first query minus
  the second, because `--since` has no upper bound) and that a review the Controller ran itself
  always shows a counted `round=N~`.
- **An unused wrapper is gone**
  ([#71](https://github.com/RodrigoFAbreu/workflow-controller/issues/71)). `_review_gate` in
  `controller/job.py` was called only by tests; they now call the functions it wrapped.

## Known limitations

Two minor findings of this milestone's reviews are kept as issues for the next clean-up milestone:

- **The common-problems entry overstates what a refused review keeps**
  ([#78](https://github.com/RodrigoFAbreu/workflow-controller/issues/78)). It says a refusal at the
  retry's re-check leaves cost and tokens in `review.telemetry`; that is true only for a Claude
  review, because a Codex review keeps no figures.
- **Adding up a review's figures can drop a token key**
  ([#79](https://github.com/RodrigoFAbreu/workflow-controller/issues/79)). A key that only the
  running total has is left out of the sum. Both attempts report the same keys today, so nothing is
  lost in practice.

## Upgrading

Nothing to do. The settings file stays at table generation 8 and the job records keep their schema
versions (1, and 2 for a review job). Install 1.13.1 as you installed 1.13.0 (see the
[update page](../update.md)). If `reviewer.same_provider_model` is set to an alias, change it to a
full model id: from 1.13.1 the review is refused before it starts instead of after it has run.
Review jobs recorded by 1.13.0 carry no figures and stay "telemetry unavailable".

**Downgrading.** 1.13.0 reads the records 1.13.1 writes. It ignores a review job's new
`review.telemetry` block, so its `telemetry` shows a Claude review as "telemetry unavailable" again.
