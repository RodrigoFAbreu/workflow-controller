# Workflow Controller 1.16.1

[Back to the documentation map](../README.md)

These notes were written after the release from the archived narrative
(`docs/milestones/completed/workflow-controller-adapters-1.md`) and the plan
(`docs/ai-workflow/CONTROLLER_ADAPTERS_1_PLAN.md`). The milestone was `workflow-controller-adapters-1` (ROADMAP A1),
accepted on 2026-10-19 by gate policy. It was released from pull request #102 (squash `70016a4`), tag `v1.16.1`. The
pull request title is `refactor:`, so this is a patch release: the Controller decides, prints and launches what it did
in 1.16.0.

## Adapters for the harness and the git host (1.16.1)

**The outside tools sit behind registries.** The Claude and Codex seams are now two adapters in one registry
(`controller/harness.py`). An adapter declares the roles it supports. Asking a harness for a role it does not declare
fails with an error that names the harness, the role and the roles it does declare, and an unknown harness name fails
with the registered names. The git host has a registry too (`controller/forge.py`, `FORGES`), with GitHub first. A
`forge_kind` that is not registered is refused, and a `forge_factory` still wins. The tables that used to be written
out by hand (the harness families and the telemetry harness names) are now derived from the registry, and equal the
old ones. See [Workers](../guide/workers.md) and [How the Controller works](../guide/how-it-works.md).

## The usage record (1.16.1)

**Every worker and review job record gets a `usage_record` key.** It sits beside `telemetry` and has one format
whatever the harness reports (`controller/usage_record.py`): harness, provider, model, token counts, wall time and
turns, each with a quality flag, and a cost. `resume --json` shows the key for a record that has it. A record that
has no `telemetry` block has no `usage_record` either.

**A failure to build it never changes a job.** If the record cannot be built, the job is kept as it was and gains a
`usage_record_failed` key.

**No cost is invented.** `controller/prices.json` ships with no models. A cost is `unknown` unless the harness reports
one; Claude's `total_cost_usd` is that figure. Nothing reads the record yet: `telemetry`, `inspect`, `status` and
`follow` still read the telemetry block. The table is maintained as described under "Maintaining the price table" in
the [development guide](../guide/development.md).

## Configuration

None. No key is added and no value moves.

## Known limitations

- **The price table is empty.** Filling it from the providers' published API list prices is
  [#103](https://github.com/RodrigoFAbreu/workflow-controller/issues/103). A cost worked out from it will be labelled
  "API list-price equivalent".
- **Small usage-record points are kept** as [#104](https://github.com/RodrigoFAbreu/workflow-controller/issues/104)
  (partial reasoning totals, what `wall_ms` means for each job kind, a half-applied rollout guard and an end-to-end
  test of a retried review). Both issues are planned before A3.
- **Not part of this release:** Codex as a worker and a second git host (A5), and the two review round caps
  ([#88](https://github.com/RodrigoFAbreu/workflow-controller/issues/88)).
- **Two tests fail locally under Git 2.56** (`test_release_notes`, `test_pull_request_lifecycle`); test only.

## Compatibility

Controller 1.16.1 admits the same Workflow releases as 1.16.0 and speaks the same protocol (1.4). See the
[compatibility page](../compatibility.md).

## Upgrading

Nothing to do. Install 1.16.1 as you installed 1.16.0 (see the [update page](../update.md)). A reader of job records
sees one new key, `usage_record` (or `usage_record_failed`). The job records keep their schema versions.
