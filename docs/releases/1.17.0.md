## Two review round caps (1.17.0)

**Each review stage has a local cap and an external cap.** `review.local_round_cap` (default 6) limits local review
rounds and `review.external_round_cap` (default 4) limits external review rounds. The options are
`--review-local-round-cap` and `--review-external-round-cap`, on `run` and `step`. Both take 1 to 100.

**They use the Workflow's split counts.** Protocol 1.5 (Workflow 2.15.0 and later) gives the local and the external
round count separately, for items created under 2.15.0 or later. The Controller checks each cap against its own count.
Without the split counts (an older Workflow, or an older item) the single round number is checked against the external
cap, as the one cap was before.

**The external review is capped too.** Before this release the cap stopped the apply and the local review only. Now a
run also stops before an external review job, and before its usage reservation, when the external count has reached
the cap.

**The stop is the same stop.** It is still the `review_round_cap_reached` gate, exit 10, with one `GATE_BLOCKED` record
and one gate notice. The text now names which cap fired, the count, the cap and where the count came from. See
[the review round cap](../run.md#the-review-round-cap) and
[a run stopped at the review round cap](../common-problems.md#a-run-stopped-at-the-review-round-cap).

**`review.round_cap` and `--review-round-cap` are deprecated.** They keep working for this release: they fill every cap
you have not set yourself. A file value of exactly 4 for `review.round_cap` cannot be told from the default, so it does
not override. They are retired after 1.17.0 (ROADMAP follow-up 59).

## Configuration

The settings table is now generation 12. It adds the `review.local_round_cap` and `review.external_round_cap` rows to
a file filled by an earlier release, both unset, so the built-in 6 and 4 apply. An older Controller that shares the file
warns about two unknown keys. See the [runtime guide](../guide/runtime.md).

## Known limitations

- **`settings show` prints the stored value** (null when unset), not the effective caps, and the stop text of the
  fallback case calls the single number "the external count":
  [#108](https://github.com/RodrigoFAbreu/workflow-controller/issues/108).
- **The split case is tested end to end at job level only** (injected snapshots). The lifecycle tests stay on the
  fallback until Workflow 2.15.0 is vendored (ROADMAP follow-up 60).
- **Two tests fail locally under Git 2.56** (`test_release_notes`, `test_pull_request_lifecycle`); test only.

## Compatibility

Controller 1.17.0 admits the same Workflow releases as 1.16.1 and uses protocol 1.5's split counts when present. This
repository runs Workflow 2.15.0. See the [compatibility page](../compatibility.md).

## Upgrading

Install 1.17.0 as you installed 1.16.1 (see the [update page](../update.md)). If you passed `--review-round-cap N` to
get room for local rounds, drop it: it now sets both caps, the external one too. With no flag the defaults 6 and 4
apply.
