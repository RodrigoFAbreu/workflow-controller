## Claude Code 2.1.304 and later pass `verify-claude` (1.19.1)

**The problem.** Claude Code 2.1.304 and later give a deny on a parent folder precedence over an allow on a child. The
tester's writable folders lay inside the denied clone, so those writes were refused. `verify-claude` (1.19.0) refused
every current build with `boundary: writable: REFUSED`.

**The writable folders now live outside the clone.** Each one is `<sandbox>/writable/<name>/`, and the clone holds a link
to it. No allowed write sits below a denied path. The deny list (the clone root and its `.git`) is unchanged, so the
tester is isolated as before.

**The post-run walk checks the links.** It accepts only the Controller's own intact links. It reports every other link,
even one whose name matches an ignore rule.

**The settings check compares resolved paths.** It compares them as well as spelled paths, at build time and again just
before launch.

**`verify-claude` has a `link` probe.** The probe checks that the link cannot be replaced. The command and the launch
now share one layout.

**The fake tester applies deny-above-wins.** The test suite therefore refuses the old layout, as the real builds do.

**Live result.** `verify-claude --force` passes all three probes on Claude Code 2.1.304, 2.1.308 and 2.1.309 and records
each digest. Claude Code 2.1.303 is no longer installed on the host, so the check against the old build was not
performed.

## Requirements

Unchanged from 1.19.0 (`bwrap`, `socat`, a kernel that accepts a seccomp filter and a `claude` build that is admitted).
`verify-claude` also needs the credential file in your Claude home.

## Known limitations

- **Two live release-side tests were skipped.** They need an API key or an OAuth token in the environment.
- **Follow-ups filed:**
  [#138](https://github.com/RodrigoFAbreu/workflow-controller/issues/138) (two timing flakes) and
  [#140](https://github.com/RodrigoFAbreu/workflow-controller/issues/140) (`remove_tree` through an intermediate link,
  the fake tester's `..` handling, and two identical tests).

## Upgrading

Install 1.19.1 as you installed 1.19.0 (see the [update page](../update.md)). Then run
`workflow-controller verify-claude --force` once per Claude build you use.
