# Workflow Controller 1.19.2

[Back to the documentation map](../README.md)

These notes were written after the release from the milestone plan
(`docs/ai-workflow/CONTROLLER_CLEANUP_3B_PLAN.md`). The milestone was
`workflow-controller-cleanup-3b`, accepted on 2026-10-24. It was released from pull request #148 (merge `d121ec8`,
title `fix: verify-claude names a host write before a sandbox error, takes --claude-binary without claude on PATH and
exits 20 on a setup error (#132, #133)`), on 2026-10-24. The title is `fix:`, so this is a patch release. It closes
issues #132 and #133. There is no behaviour change outside `verify-claude`.

## `verify-claude` reports setup problems clearly (1.19.2)

**A host write is named.** When the sandbox failed to start, `verify-claude` hid a write to the host behind
`inconclusive`. It now names the host write in the error (#132).

**The host-listener folder is short.** The folder is short whatever `TMPDIR` is, so a deep `TMPDIR` no longer fails
with `AF_UNIX path too long` (#132).

**`--claude-binary` needs no `claude` on `PATH`.** The command verifies the named build. It notes that functional
review cannot start until a `claude` is put on `PATH` (#133).

**A setup error is a refusal.** An `OSError` while the probe run is built (a full disk, an unwritable folder, a listener
that cannot bind) is reported as the `host` probe and exits `20`. It no longer ends in a traceback (#133).

**The live tests skip without credentials.** Without the credential file every live probe skips. The
[development guide](../guide/development.md) and the [commands guide](../guide/commands.md) now say so.
