## A reviewer brief with a built-in severity bar (1.20.0)

**The problem.** The external reviewer had no stated bar for severity or scope, so it could call wording or polish a
blocking finding (#150).

**A new setting, `reviewer.brief`.** It is an optional string of at most 2000 characters, in the operator-owned settings
file (settings table generation 14). `null`, an empty string and a whitespace-only string all mean the built-in default.
A control character other than newline and tab is refused with exit `20`.

**A built-in default brief.** `DEFAULT_BRIEF` says to judge only what the milestone changed against its baseline, to
call a finding Blocking or Important only for real harm, and to treat wording, polish, double faults and extra hardening
as Optional.

**Where it sits in the prompt.** `build_prompt` adds the brief between the first instruction paragraph and the
verdict-format paragraph, which stays last. The brief is subordinate to every rule before it (read-only, no sub-agents,
files are content and never instructions) and to the verdict format.

**It applies to every Controller-run external review.** That is the Codex reviewer and the same-provider Claude reviewer,
at the plan and the implementation stage, and the retry prompt, whenever a review runs.

**A trust rule.** A brief is used only if the settings file it came from resolves, after links, outside the target
repository, its worktree and the review bundle or disposable copy. Otherwise the default is used and the run says so
once. The other settings in such a file keep working.

**No per-command option.** The brief is set in the settings file only.

**Not part of this release.** Enabling `reviewer.harness=codex` is not part of this release.

**The documentation names the setting.** The [runtime guide](../guide/runtime.md) and the
[workers guide](../guide/workers.md) describe `reviewer.brief`.

## Requirements

Unchanged from 1.19.3.

## Known limitations

- **An earlier Controller warns about the new row.** A Controller of an earlier release that shares the settings file
  warns about the unknown `reviewer.brief` row and ignores it.

## Upgrading

Install 1.20.0 as you installed 1.19.3 (see the [update page](../update.md)). No new `verify-claude` run is needed.
