# Workflow Controller 1.21.0

[Back to the documentation map](../README.md)

These notes were written after the release from the milestone plan
(`docs/ai-workflow/CONTROLLER_ROUTING_HARNESS_PLAN.md`). It was released from pull request #160 (merge `fb263bc`, title
`feat: a routing entry names a harness, checked against the roles the adapter declares (#158)`), on 2026-10-25. The
title is `feat:`, so this is a minor release. It closes issue #158. A routing entry gains a `harness` field that is
checked and recorded. Nothing launches on another harness yet.

## A routing entry names a harness (1.21.0)

**The problem.** A routing entry named a model and an effort but not the harness that runs them (#158).

**A new `harness` field.** A routing entry now has `harness` beside `model` and `effort`. It is set in the `routing`
section of the settings file, in a routing config file, and with the new command-line option `--role-harness
ROLE=HARNESS`. The default stays `claude-code`.

**It is checked against the roles the adapter declares.** The check uses the registry in `controller/harness.py`.
`claude-code` is accepted for every routing role. `codex` is accepted for none: the Codex adapter declares only the
reviewer role, and no routing role launches as the reviewer adapter role.

**A refusal is named.** An unknown harness, or a role and harness pair the adapter does not declare, is refused at load
with exit `20`. This holds for every source. A value is never dropped silently.

**Precedence.** `--role-harness` first, then the role entry in the routing config, then the routing config's default,
then the settings, then `claude-code`.

**The record.** The resolved route (`ResolvedRoute`) and the job record gain `harness` and `harness_source`. The
addition is additive.

**Nothing launches on another harness.** Launch ignores the resolved harness. Launching on another harness belongs to
later items.

**The documentation.** The [commands guide](../guide/commands.md) and the [runtime guide](../guide/runtime.md) describe
the field and the option.

## Requirements

Unchanged from 1.20.0.

## Known limitations

- **An earlier Controller warns about the new field.** The settings table generation is now 15. A Controller of an
  earlier release that shares the settings file warns about the unknown `harness` field and ignores it.

## Upgrading

Install 1.21.0 as you installed 1.20.0 (see the [update page](../update.md)). No new `verify-claude` run is needed.
