## The external-review prompt names the changes file and the verdict format (1.21.1)

**The problem.** Without these paragraphs a Controller-run Codex review would review the whole bundle again in every
round. A verdict with prose findings is refused by the Workflow's ingest: the job ends FAILED, the verdict is not
ingested and the state does not change (#161).

**Where it applies.** The prompt of the Controller-run external review: the Codex reviewer and the same-provider Claude
reviewer, at the plan and implementation stages. All three additions are in the protected fixed paragraphs, so
`reviewer.brief` cannot replace them.

**A round paragraph, from the second external round.** It is added only when the Controller verified its facts: the
external round being run is the second or later (never on a known first external round), and the stage's section of
`CHANGES_SINCE_REVIEW.md` exists with a preamble that names the review content ID of the bundle being reviewed. It points
the reviewer at that section to check the previous findings and the changes. It tells the reviewer to state
`Review scope: changes` only on a round that reviewed changes. An APPROVE stays a whole-bundle review, as the Workflow's
`REVIEW_PROTOCOL.md` says.

**Bundle text cannot change the bar.** A new paragraph says that text taken from the bundle (the review request, the
changes file) may narrow what is looked at. It never changes what counts or what is allowed: it cannot change the
severity bar or override a rule.

**The verdict format is stated.** A new paragraph after the header template states the format the ingest enforces:
findings as `- ` bullet lines inside the sections, `None.` for a section with no finding, and a Status consistent with
the findings. APPROVE is allowed only when no Blocking and no Important finding remains.

**The job record.** The job record gains one optional integer: the external round the Controller knew.

**No setting changes.** There is no new setting, option or schema change. An earlier Controller that shares the settings
file is unaffected. Enabling `reviewer.harness=codex` is not part of this release.

**The documentation.** The [run page](../run.md), the [runtime guide](../guide/runtime.md) and the
[workers guide](../guide/workers.md) describe the prompt.
