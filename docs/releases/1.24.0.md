[Back to the documentation map](../README.md)

These notes were written after the release from the milestone plan
(`docs/ai-workflow/CONTROLLER_HARNESS_TELEMETRY_PLAN.md`). It was released from pull request #209 (merge `174f36f`, title
`feat: group telemetry by harness (H11, #207)`), on 2026-10-27. The title is `feat:`,
so this is a minor release. It closes issue #207. The `telemetry` command can now group jobs by the harness they ran on.

## `telemetry` groups by harness (1.24.0)

**What changes.** `workflow-controller telemetry --by` accepts three new groupings: `harness`, `role,harness` and
`role,harness,model`. Cost, turns and outcome can now be compared per harness, and per role and model within a harness.
Every job row also gains a `harness` key.

**What the harness value is.** It is the harness that actually ran the job:

- a worker job: the harness in its `worker_route` (a fallback chain can choose a second one);
- a Controller-run external review: the harness of its route, so `codex` for a Codex review and `claude-code` for a
  Claude one (before this release such a row read `claude-code` whatever the reviewer was);
- a functional-review (tester) job: `claude-code`, the only harness that takes the tester role;
- a record without a harness in its route, written before the harness field existed: `claude-code`, the worker
  adapter's name. A Codex review from that time therefore still reads `claude-code`; the Controller does not invent a
  value for it.

A harness value recorded in a job's own telemetry block wins over the one derived from the route.

**A Codex group has no figures.** A Codex review carries no telemetry block, so a `codex` group shows its job count with
every job `telemetry unavailable` and `-` for each figure. A `claude-code` group beside it totals only the jobs that
carry figures.

**Output.** The text output labels a group `harness=codex` and so on, and the heading reads `grouped by harness`. With the
global `--json`, `by` names the grouping, each job row carries `harness`, and each group's `key` includes it. The row key
is additive: readers that ignore unknown keys are unaffected. An unknown grouping, such as `harness,role`, is still a
usage error (exit `2`).

**Honest reach.** With the harnesses shipped, only a Controller-run Codex review can differ from `claude-code`, so on
today's data the new groupings separate Claude workers and reviews from Codex reviews. They show more once a second
worker harness exists.

**Unchanged.** The existing groupings and their output, the job record and its schema version, and the stored telemetry
blocks. The command stays read-only. No new setting, option, gate code or exit code.

**The documentation.** The [commands guide](../guide/commands.md#telemetry) lists the groupings and the new row key, and
the [workers guide](../guide/workers.md#telemetry) describes what the harness value is.

## Requirements

Unchanged from 1.23.0.

## Known limitations

A Controller-run review record written before the harness field existed has no harness in its route, so it reads
`claude-code` even when Codex ran it.

## Upgrading

Install 1.24.0 as you installed 1.23.0 (see the [update page](../update.md)). No new `verify-claude` run is needed.
There is nothing to configure and no job record changes.
