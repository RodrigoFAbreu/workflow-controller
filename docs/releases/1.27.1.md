# Workflow Controller 1.27.1

[Back to the documentation map](../README.md)

These notes were written after the release from the milestone plan
(`docs/ai-workflow/CONTROLLER_USER_ONLY_SCAN_PLAN.md`). It was released from pull request #249 (merge `07a87a2`, title
`fix: refuse a user-only command named with wrapping punctuation (TK1, #247)`), on 2026-11-01. The title is `fix:`, so
this is a patch release. It closes issue #247. Only the scan that keeps a model from running a user-only command changes.

## A user-only command named with wrapping punctuation is refused (1.27.1)

**The problem.** The scan that keeps a model from running a user-only command named inside a task or an argument string
missed a name that was followed or wrapped by some punctuation. It stripped only a leading `` ` `` and `/` and a few
trailing characters (`` ` ' " , . ; : ) ] } ``) from each whitespace-separated word, so `/approve-review!`,
`/approve-review?`, `(/approve-review)`, `"/approve-review"`, `[/approve-review]` and `--x=/approve-review` were not
recognised and the task was not refused (#247).

**What is refused now.** The scan splits each whitespace-separated word on `=` and on every character that is not a
letter, digit, `_`, `-`, `.` or `/`, then strips `/`, `-` and `_` from the front of each piece and `/`, `.`, `-` and `_`
from its end. A name wrapped in `!`, `?`, brackets, quotes, angle brackets or markup, behind an `=`, or with a dash or
underscore around it (`/name!`, `(/name)`, `<name>`, `**/name**`, `--x=/name`, `--name`, `_name_`) is found and the task
is refused as before, before any process starts. `~/name` is also refused, because `~` delimits.

**What is deliberately not refused.** A name inside a longer word or path is not a mention: `approve-reviewer`,
`docs/ai-workflow/approve-review.md`, `approve-review.md`, `foo/approve-review-bar`, `a/approve-review`, and the relative
paths `./approve-review` and `../approve-review`. A task that names no user-only command is judged exactly as before.

**Where it applies.** The Claude worker launch and the Codex command renderer use the same tokeniser, so both get the fix.
The set of user-only names, the refusal text and the evidence are unchanged.

**Unchanged.** There is no new setting, option, exit code, step count, gate identity or route.

**The documentation.** The [workers guide](../guide/workers.md) states the rule where it describes the scan.

## Requirements

Unchanged from 1.27.0.

## Known limitations

A name glued to letters (inside a longer word) is still not seen; that is the existing whole-token rule. The nested
invocation limit the workers guide states is unchanged.

## Upgrading

Install 1.27.1 as you installed 1.27.0 (see the [update page](../update.md)). No new `verify-claude` or `verify-codex`
run is needed. There is nothing to configure. A task or argument string that names a user-only command in one of the
spellings above is now refused where it was not.
