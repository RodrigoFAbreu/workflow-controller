# Workflow Controller 1.27.3

[Back to the documentation map](../README.md)

These notes were written after the release from the milestone plan
(`docs/ai-workflow/CONTROLLER_CHECKLIST_RECOGNISER_PLAN.md`). It was released from pull request #270 (merge `7239a97`, title
`fix: the functional checklist recogniser accepts F1, 3a and 6.1 style labels and refuses a partly recognised checklist (FL1, #227)`),
on 2026-11-02. The title is `fix:`, so this is a patch release. It closes issue #227. Only the reading of the
"Functional review checklist" section changes.

## The functional checklist is read whole, or refused (1.27.3)

**The problem.** The Controller reads the flows of the "Functional review checklist" section before it runs the functional
tester. Two defects came from one mechanism (#227). A label was recognised only when it was one letter or one or two
digits, so rows labelled `F1`, `3a`, `5b`, `6.1` or `6b-split` were skipped without a word. And a shape that recognised
some of its items dropped the others: a table of nine flows of which three had a known label was read as a complete
checklist of three flows, the tester ran three, and the round could pass on 3 of 9 flows, with evidence for the rest never
produced. A table whose rows were all `F1`, `F2` was refused as having no flow at all.

**What is accepted now.** A flow label is a letter with up to two digits, or a number of one or two digits with dotted
parts and one optional letter, either with one hyphenated qualifier. It applies to the first cell of a table row, to a bold
label (`**F1.`) and to a heading label.

| Label | Accepted |
|---|---|
| `A`, `7` | yes |
| `F1`, `3a`, `6.1` | yes |
| `6b-split` | yes |
| `Flow 4`, `long`, `123` | no (a word, or a number of three digits) |

The numbered list keeps its number as the marker and gains the digit-led forms (`3a.`, `6.1.`). A heading `Flow 6.1` now
carries the label `6.1`, so `Flow 6.1` and `Flow 6.2` are two flows. Flow ids stay `flow-1`, `flow-2` in order of
appearance, and a flow's label is kept as written.

**What is refused now.** When the shape that finds flows leaves an item that looks like a flow but is not a label (a table
row whose first cell is not a label, a continuation row with an empty first cell, a bold label or heading such as `123.` or
`A1b2.` that has a digit but is not a label), the Controller refuses the checklist with the existing
`checklist_unrecognised` gate instead of testing only the recognised part, before any job, sandbox or usage reservation
exists. The stop opens "the functional review checklist is only partly recognised", names the unrecognised items (the
first eight in the message, then a count) and the count recognised against the total, and its evidence carries `shape`,
`recognised`, `total` and `unrecognised`. A checklist with no flow still stops as before, and when a table was seen its
message now names the first cells it found.

**What is deliberately not a flow or a refusal.** Words and sub-labels inside a flow (`**Expected:**`, `**Verify.**`,
`**Setup.**`: more than one letter and no digit) and prose are never read as flows. The optional, qualified flow header
(`**Optional, K. Title.**`) is not run and not refused: it still ends the flow before it. A case table inside a flow of a
bold, heading or numbered checklist stays part of that flow's text. When the checklist is made of bold, heading or numbered
flows, a table row outside every flow is refused, not guessed at.

**Unchanged.** There is no new setting, option, exit code or gate, and the refusal keeps its code, shape list and remedy.

**The documentation.** The [automation guide](../guide/automation.md#protocol-mode-workflow-27-and-later) states the label
rule and the partly-recognised stop, and the [common problems](../common-problems.md#the-run-stopped-at-the-functional-review-row-38e)
and [troubleshooting](../guide/troubleshooting.md) pages mention it.

## Requirements

Unchanged from 1.27.2.

## Known limitations

A flow of a shape that does not decide can still be dropped when another shape decides the checklist; this cross-shape
case is tracked in issue #271.

## Upgrading

Install 1.27.3 as you installed 1.27.2 (see the [update page](../update.md)). No new `verify-claude` or `verify-codex`
run is needed. There is nothing to configure. A checklist that was silently partly run before may now stop at
`checklist_unrecognised`: fix the labels or the table the message names, or run the flows by hand.
