# Workflow Controller 1.27.5

[Back to the documentation map](../README.md)

These notes were written after the release from the milestone plan
(`docs/ai-workflow/CONTROLLER_CLEANUP_3C_PLAN.md`). It was released from pull request #277 (merge `8afb0f4`, title
`fix: fill the price table, tidy the usage record and show the round caps in force in settings show (#103, #104, #108)`),
on 2026-11-03. The title is `fix:`, so this is a patch release. It closes issues #103, #104 and #108.

## The price table is filled (1.27.5)

**The problem.** The price table, `controller/prices.json`, had no prices in it (version 1). A cost derived from it was
`null` for every model the Controller launches by default (#103).

**What changed.** The table is now version 2, dated 2026-11-03. It holds the API list prices of the four default models:
`gpt-6.1-sol`, `claude-opus-5-5`, `claude-sonnet-5-5` and `claude-haiku-5-5`, each with an input, cache read, cache write
and output price per token. Two of them are priced by prompt length, and they are entered at their lower tier only:
`gpt-6.1-sol` up to 272K tokens and `claude-haiku-5-5` up to 100K tokens, so a cost derived from the table is a lower bound
for longer prompts. The cache write price is the shortest-duration rate (five minutes for Claude, 30 minutes for
`gpt-6.1-sol`). A model absent from the table, and an alias such as `opus`, `sonnet` or `haiku`, still gives cost `null` and
quality `unknown`.

**A test keeps it filled.** A test now requires a complete price for every default model, read from the modules, so a new
default model added without a price fails the test suite.

**What the cost means.** A cost derived from the table is an API list-price equivalent: what the same tokens would cost at
the provider's published API prices. It is not what a subscription charges. The guides now say so wherever they name the
cost (#104).

## The usage record is tidied (1.27.5)

- Reasoning tokens are `unknown` unless every result reports them. Before, a sum over only the results that carried the
  figure could be recorded as if it were complete. A review whose attempt had a result without the figure now records the
  sum as unknown, with no partial sum, as the worker record already did (#104).
- The wall time keeps a different source for each kind of job, and the code and the [workers guide](../guide/workers.md)
  now say which: the summed `duration_ms` of a Claude worker's results, the Controller's own elapsed monotonic time for a
  Codex worker, and launch to the terminal write in whole seconds for a review, for a Claude review as for a Codex one.
- A Codex rollout that is not a mapping is skipped explicitly when the usage is read.

## `settings show` prints the round caps in force (1.27.5)

**The problem.** `settings show` printed the three stored `review.*round_cap` rows, and an unset cap showed as
`null (default)`. That could be read as no cap at all (#108).

**What changed.** After those rows, `workflow-controller settings show` prints one line per review round cap a run uses,
for example `review.local_round_cap in force = 6 (built-in)`. The origin is `built-in`, `its own setting or option` or
`deprecated review.round_cap`. The stored rows are unchanged, and the deprecated row now carries a note. With `--json`,
the output gains the key `round_caps_in_force` (`{"local": {"cap": N, "origin": ...}, "external": {...}}`). The caps a run
uses and the lines shown come from the same rule, and a test checks that they are equal. `settings show` can only show
the origins a settings file and the built-in defaults give: a cap given as a `run` or `step` option is not an option of
`settings show`.

**The cap-stop wording.** When a run stops at the `review_round_cap_reached` gate, the text now says which round reached
which cap, for example `plan review external round 4 has reached the external round cap of 4`, instead of naming a
"count". With the single fallback number, it reads `plan review round 4 has reached ...`.

**Unchanged.** There is no new setting, option, exit code or gate.

**The documentation.** The [commands guide](../guide/commands.md#settings), the [runtime guide](../guide/runtime.md),
the [workers guide](../guide/workers.md), [how it works](../guide/how-it-works.md) and the
[common problems](../common-problems.md) page describe the above.

## Known limitations

## Upgrading

Install 1.27.5 as you installed 1.27.4 (see the [update page](../update.md)). No new `verify-claude` or `verify-codex`
run is needed. There is nothing to configure. Derived costs now appear for the four default models where they were
`null` before; read them as API list-price equivalents.
