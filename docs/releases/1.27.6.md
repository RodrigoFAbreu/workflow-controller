# Workflow Controller 1.27.6

[Back to the documentation map](../README.md)

These notes were written after the release from the milestone plan
(`docs/ai-workflow/CONTROLLER_TESTER_READ_DENIES_PLAN.md`). It was released from pull request #279 (merge `4a91b26`, title
`fix: the functional tester cannot read credentials, a file:// origin is checked and the summary is bounded (C10h, #115)`),
on 2026-11-03. The title is `fix:`, so this is a patch release. It closes issue #115.

## The Claude functional tester cannot read credentials (1.27.6)

**The problem.** The sandbox of the Claude functional tester limited what it could write, but not what it could read. The
tester could read the copy of your login that the job keeps, your account files and your Claude home (#115).

**What changed.** The tester's settings now carry a `sandbox.filesystem.denyRead` list, built by
`functional_review.read_denies`. It denies reads of:

- the job's own `.credentials.json`, `.claude.json` and `backups` in its private Claude home,
- your whole Claude home (`CLAUDE_CONFIG_DIR`, else `~/.claude`), and
- your global account file, `~/.claude.json`.

Each entry is followed by its resolved form when that differs. When your `.credentials.json` is a link to a file outside
your Claude home, that target is denied too. The rest of the job's home stays readable, because the shell the CLI starts
keeps its own working files there.

**A settings invariant.** The existing rule that no write allowance may lie at or below a denied path now covers the read
denies as well, so the settings mean the same on every supported build. A launch also checks that the settings it was
given carry exactly this read deny list.

**A runtime root inside your Claude home is refused.** The deny would cover the tester's own folders, so a functional
launch with such a runtime root is refused as `functional_tester_unavailable`, and `claude-build verify` refuses it as a
host problem.

**The test double and `claude-build verify`.** The fake functional tester used by the tests now emulates the read deny
(a new `read` action is refused when a `denyRead` entry is the path or an ancestor of it), and the tests check the
settings against it. `claude-build verify` builds its test launch with the same read denies as a real launch, and a test
checks that they are equal. The enforcement on the pinned Claude Code build is also checked by an opt-in live test
(`CONTROLLER_LIVE_CLAUDE_TESTS=1`).

## A `file://` origin is read as a local path (1.27.6)

The before-and-after comparison of the real repository's `origin` reads a local path origin only. A `file://` origin was
skipped as if it were a network URL. It is now read as a local path, with the part after the scheme percent-decoded and the
authority ignored, as Git does. A `file://` origin that names no absolute path, or whose path holds a NUL byte, is
reported as an `origin` breach instead of being skipped.

## A tester summary is bounded (1.27.6)

A tester's `summary` for a flow is cut to 2000 characters where it enters the Controller, followed by a marker that states
how many characters were omitted. A summary within the limit is unchanged. The flow's log file is not changed.

The documentation: the [automation guide](../guide/automation.md#what-the-controller-automates-and-how-it-stays-safe) and
the [harnesses guide](../guide/harnesses.md) describe the above. The read deny is for the Claude tester only; the Codex
tester's profile already restricts reads. The summary bound and the `file://` check apply to both testers.

## Requirements

Unchanged from 1.27.5.

## Known limitations

- The credential copies that other Controller jobs keep under the shared runtime root (`reviews/<job>/claude-home/`, a
  `verify-*` scratch folder, and any copy a killed job left behind) are still readable by absolute path, and so are other
  credential stores such as `~/.ssh` and `~/.config/gh`. Closing that needs a read allowlist. It is recorded as a
  follow-up in the [roadmap](../ROADMAP.md#known-follow-ups-carried-forward).
- The read deny binds the tester's shell, not the Claude process itself.

## Upgrading

Install 1.27.6 as you installed 1.27.5 (see the [update page](../update.md)). There is nothing to configure. If your
runtime root lies inside your Claude home, move it: a functional launch with it is now refused.
