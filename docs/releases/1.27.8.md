These notes were written after the release from the milestone plan
(`docs/ai-workflow/CONTROLLER_CHECKLIST_FLOW_ENDS_PLAN.md`). It was released from pull request #284 (merge `f61a99d`, title
`fix: functional checklist flow ends are read or refused and a link above the checklist's folder is followed (C10j, #116)`),
on 2026-11-04. The title is `fix:`, so this is a patch release. It closes issue #116.

## The functional checklist reader finds where a flow ends (1.27.8)

**The problem.** The reader of the functional review checklist could drop text silently: a bold line such as
`**Setup** for this flow: ...` or `**Setup: none needed.**` after a blank line ended a flow and its text was held by no
flow, so the tester never saw it. A qualified header written without the comma (`**Optional K. Title.**`) or with more
than one word did not end the flow before it, so an optional flow was folded into the one above. A link such as
`../tests/checklist.md`, which is inside the repository, was refused (#116).

**What changed.**

- **One definition of a flow header.** A bold header may carry a qualifier: one or two words of letters and a comma
  (`**Optional, K. Title.**`), or one of `Optional`, `Required`, `Extra`, `Additional` and `Conditional` with no comma
  (`**Optional K. Title.**`). The line that starts a flow and the line that ends the flow before it now use the same
  definition, so a header that ends one flow always starts the next.
- **Text between two flows is refused.** In a checklist read by its bold flow headers, a line between two flows that no
  flow holds stops the step at `checklist_unrecognised`. The message names the first such line, the flow before it and the
  flow after it, and the evidence lists the lines under `interior`. A blank line, a heading and a lone `**Flows**`
  introducer line may stay between two flows. Text before the first flow and after the last one is read as before.
- **A link above the checklist's folder is followed.** A checklist section whose only content is a link to another file
  resolves the link from the checklist's own folder, so `../tests/checklist.md` in `docs/ACTIVE_MILESTONE.md` names
  `tests/checklist.md`. A link that ends outside the repository, or at a file that is not tracked, still ends at
  `checklist_unrecognised`, and the message now says how a link is resolved.
- **A missing section names its heading.** When the checklist has no section, the message names the heading to write
  (`Functional review checklist`, at any heading level and in any case) and lists up to five headings that contain
  `checklist` with `functional` or `review`, with their line numbers.
- **A case-folding character no longer ends a flow early.** A character such as U+212A (the Kelvin sign) or U+017F (the
  long s) in a header was read as a letter of a section word and could end the flow before it. Section words and
  qualifier words are now matched in ASCII case only.

## Requirements

Unchanged from 1.27.7.

## Known limitations

- The tester runs an optional flow as it runs any other, so an optional flow that cannot run in the sandbox can stop a
  round that used to pass over it.

## Upgrading

Install 1.27.8 as you installed 1.27.7 (see the [update page](../update.md)). There is nothing to configure. A checklist
that has text between two flows now needs that text moved into a flow, or to the end of the checklist.
