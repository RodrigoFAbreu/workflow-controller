# Workflow Controller 1.27.9

[Back to the documentation map](../README.md)

These notes were written after the release from the milestone plan
(`docs/ai-workflow/CONTROLLER_REMOVE_TREE_LINKS_PLAN.md`). It was released from pull request #287 (merge `bc64e12`, title
`fix: remove_tree refuses a path below a symbolic link (C10k, #140)`), on 2026-11-04. The title is `fix:`, so this is a
patch release. It closes issue #140.

## Removing a path below a symbolic link is refused (1.27.9)

**The problem.** The Controller's folder-removal primitive, `runtime.remove_tree`, checked that the path it was given stayed
inside its root, but it resolved the folder above the last component first. A path whose parent chain held a symbolic link
(for example `clone/build/x`, where `clone/build` is a link to a folder elsewhere inside the root) was therefore followed
through the link, and the contents of the folder the link points to were removed (#140).

**What changed.**

- **A link in the parent chain is refused.** `remove_tree` now looks at every component of the path above the last one,
  below the root, before it removes anything. A symbolic link among them stops the call with a containment error that names
  the link. Nothing is removed: the link and the folder it points to are untouched.
- **A `..` component is refused.** A path with a `..` component stops with the same kind of error.
- **A link as the last component is unchanged.** It is unlinked and the folder it points to is kept, unless the link leads
  outside the root, which the containment check still refuses and the link stays.
- **A path that is already gone is still not an error.**

One production path changes: a Codex review removes `.agents/skills` and `.agents/plugins` from its private copy of the
worktree. If the worktree's `.agents` is itself a symbolic link, the review now fails when it builds that copy (the job
record is `FAILED`, `outcome: error`, `not_started: true`) and nothing is spent. A worktree whose `.agents` is a real
folder is not affected.

The documentation: [common problems](../common-problems.md#a-review-the-controller-ran-did-not-finish) names the refusal
with its cause and remedy.

## Requirements

Unchanged from 1.27.8.

## Known limitations

- A change between the check of the parent chain and the removal itself is not guarded against.

## Upgrading

Install 1.27.9 as you installed 1.27.8 (see the [update page](../update.md)). There is nothing to configure. If a Codex
review fails with `refusing to remove ... is a symbolic link`, remove the `.agents` link from the repository or replace it
with a real folder.
