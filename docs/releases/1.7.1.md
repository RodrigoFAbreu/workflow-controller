## A `warn` check no longer stops the Controller (1.7.1)

**A `warn` check is advisory.** A Workflow `verify` check can have the status `warn`
(protocol 1.1, Workflow 2.8.0 and later). Controller 1.7.0 did not know that status and refused
with exit 20. Now `explain`, `step` and `run` go on. Every decision's evidence carries a
`verify <check>: warn: <detail>` line, and the same line is kept in the job record.

**The unhealthy gate lists both kinds of check.** When `verify` says the repository is not
healthy, the gate lists the failing checks first, then the `warn` checks. It says that the `warn`
checks are advisory. A status the protocol has not defined is still refused with exit 20.

**Known causes of `warn`.**
- A gate-policy file that is not adopted yet.
- A gate-lowering adoption, while it is the newest adoption.
- A review verdict recorded without a run ref.

## Workflow 2.9.0 (protocol 1.2)

**The new schema is vendored.** The Workflow 2.9.0 protocol schema (protocol 1.2) is copied
byte for byte. Its eight new action ids are in the catalogue.

**`inspect` says what this release cannot launch.** It now lists "action ids this Controller
release cannot launch". These are the four automatic ids (`acceptance.satisfy`,
`implementation.satisfy`, `plan.satisfy` and `pr.apply_review`) and any invented id. Release 1.7.0
said "does not know".

## Small changes

- A `healthy: false` answer with neither `fail` nor `warn` now reads "no check names a cause".
  It used to read "unhealthy ()".
- The job path and `explain` now share one decision entry point.
- The task and reference pages document Workflow 2.9.0. Controller 1.7.0 and 1.7.1 both admit
  2.9.0.

## Upgrading

No settings or state format changes. Install 1.7.1 as you installed 1.7.0 (see the
[update page](../update.md)).
