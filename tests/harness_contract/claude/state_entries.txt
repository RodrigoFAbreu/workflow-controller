## Readings
- CLAUDE_CONFIG_DIR is honoured: every config/state file lands in <home>/.claude/, including the global config
  .claude.json (which without CLAUDE_CONFIG_DIR lives at $HOME/.claude.json) and its backups/.claude.json.backup.<ms>.
  .claude.json is rewritten several times per run (atomic temp+rename, mode 0600; run 7 debug) and holds machineID,
  userID, firstStartTime, pluginUsage and the account profile (oauthAccount: accountUuid, emailAddress, organizationUuid,
  displayName, ...).  It is NOT a credential but carries account identity: treat as private, never copy back.
- --no-session-persistence (runs 2-7): no transcript is written.  Without it (runs 1, 8): projects/<cwd slug>/<session
  id>.jsonl (the full transcript; 50 KB for a one-line answer in run 8, 202 KB in run 1).  Run 1 (Bash offered) also
  wrote session-env/<session id>/.
- Auto-memory creates an empty projects/<slug>/memory/ even with --no-session-persistence (runs 2, 3, 5, 6);
  CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 suppresses it (runs 7, 8).
- .last-cleanup appears in some runs (1, 2, 3, 5, 6) and not others (4, 7, 8): a periodic cleanup marker, not tied to a flag
  observed here.
- sessions/ (empty) and tmp/cc-socks/ (the uds-messaging socket <pid>.sock lives there while the run is up; removed at
  exit) and tmp/claude-1000/ are created by every run, the not-logged-in run 4 included (no cc-socks there).
- XDG_CACHE_HOME is used only for MCP server logs (claude-cli-nodejs/<slug>/mcp-logs-*/); with MCP isolated (runs 2-8)
  nothing is written there.  XDG_CONFIG_HOME and XDG_STATE_HOME stayed empty in all runs.
- mcp-needs-auth-cache.json appears only when claude.ai connectors were loaded (run 1).
- The credential file .claude/.credentials.json is never rewritten (see credentials.txt).
- The copy (cwd) was byte-for-byte unchanged in every isolated run (find listing identical before/after); in runs 1 and 3
  only the hook and MCP marker files appeared.  No written.txt in any run.
