# The read-only composing command (codex-cli 0.162.1)

There is no `codex config` subcommand and `codex doctor`/`codex debug` do not print per-key sources. The command that
composes every layer and prints the effective values WITH their source layer is the app-server JSON-RPC method
`config/read` with `includeLayers: true`, over stdio, after `initialize`:

  <binary> app-server --strict-config <the same -c/--disable overrides as the exec> --listen stdio://
  stdin:  {"id":1,"method":"initialize","params":{"clientInfo":{"name":"c7-prestep","version":"0"}}}
          {"method":"initialized"}
          {"id":2,"method":"config/read","params":{"includeLayers":true,"cwd":"<copy>"}}
          {"id":3,"method":"configRequirements/read"}
  then close stdin (the server exits 0).
  Response: result.config (every key, defaults included), result.origins (LEAF dotted key -> {name: ConfigLayerSource,
  version: sha256}), result.layers ([{name, version, config, disabledReason}], highest precedence first).

Flags this invocation kind accepts: -c, --enable, --disable, --strict-config (accepted; an unknown -c key fails), --listen.
It does NOT accept --ignore-rules, -s, -C, -m, -p is not offered. Run it with the same env and the same minimal home.
No auth is needed (it ran in a home without auth.json).

Does not start anything: with CODEX_HOME pointing at a hostile home (an MCP server, a SessionStart hook, top-level notify
and a custom provider, every command a marker script that writes outside the copy and opens a connection), config/read
reported all of them with source "user" and NO marker was written (sandbox_probe.txt C1). It does write Codex state into
the home (installation_id, *.sqlite state DBs, tmp/; skills/.system/ unless skills.bundled.enabled=false; .tmp/git-*
and .tmp/plugins.sync.lock when the plugins feature is on) and sends one remoteControl/status notification (disabled).

ConfigLayerSource variants in the schema (v2/ConfigReadResponse.json): packagedDefaults{file}, mdm{domain,key} (macOS
only), system{file} (/etc/codex/config.toml), enterpriseManaged{id,name}, user{file,profile}, project{dotCodexFolder},
sessionFlags (-c/--disable), legacyManagedConfigTomlFromFile{file} (/etc/codex/managed_config.toml),
legacyManagedConfigTomlFromMdm. requirements.toml is not a config layer: it is read by configRequirements/read
(result here: {"supportsIndependentSpeedModes": true, "requirements": null}).

Packaged defaults are NOT listed as a layer and have no origin, but they set values: chatgpt_base_url =
"https://chatgpt.com/backend-api/", project_root_markers = [".git"], cli_auth_credentials_store="file",
mcp_oauth_credentials_store="auto", history.persistence="save-all", include_*_instructions=true, ... (embedded text
"# Fixed defaults for packaged Codex clients." in the binary). A values-only check of FORBIDDEN_EFFECTIVE_KEYS would
therefore refuse every launch on chatgpt_base_url; the check must use origins (a key is "set" when some layer other than
the packaged defaults is its origin) or allow the packaged default value.
Empty arrays/tables (notify=[], mcp_servers={}) have no origin entry; arrays get per-index origins (notify.0, ...).
