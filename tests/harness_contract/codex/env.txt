# Environment the installed codex needs (codex-cli 0.162.1)

command -v codex      -> /home/rodrigo/.nvm/versions/node/v24.14.0/bin/codex (symlink)
readlink -f           -> /home/rodrigo/.nvm/versions/node/v24.14.0/lib/node_modules/@openai/codex/bin/codex.js
first line            -> #!/usr/bin/env node
interpreter           -> node, resolved through PATH: /home/rodrigo/.nvm/versions/node/v24.14.0/bin/node (same dir as the codex symlink)
native binary         -> spawned by codex.js from node_modules/@openai/codex-linux-x64/vendor/x86_64-unknown-linux-musl/bin/codex
                         (static-pie musl; found relative to codex.js, NOT via PATH); bundled bwrap in codex-resources/
codex.js adds         -> CODEX_MANAGED_PACKAGE_ROOT=<package root> and CODEX_MANAGED_BY_NPM=1 (the fallback name when
                         no package manager is detected) to the native child's env; harmless

review.interpreter_dir(binary): the shebang is '#!/usr/bin/env node', so it returns None by design and PATH is
[dirname(binary)] + SYSTEM_PATH. resolve_binary returns the unresolved symlink path, so dirname is the nvm bin dir,
which also holds node: correct. (If the Controller passed the readlink -f path, dirname would be .../codex/bin, which
has no node, and the launch would fail: keep the symlink's directory, or add dirname(command -v node).)

Notes:
- The sandboxed shell is the passwd login shell (/usr/bin/zsh) started as a LOGIN shell (-lc): allow_login_shell
  defaults to true, so zsh reads /etc/zsh/zprofile and the private HOME's dotfiles (empty in the Controller home).
  -c allow_login_shell=false is available (key exists in the composed config) but was not exercised.
- Inside the sandbox Codex sets CODEX_SANDBOX_NETWORK_DISABLED=1 (binary string; not inspected at runtime).
- ELF interpreter: none (static-pie), so no loader dir is needed on PATH.
