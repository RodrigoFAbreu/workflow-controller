# Codex tester composed configuration, codex-cli 0.163.0 (C10g-3a)

Measured 2026-10-30 with no model call and no spend. Setup: a real tester job built by `codex_sandbox.build`
(runtime root under ~/.cache, a one-commit git clone, the operator's `auth.json` copied into the tester home), then
the reviewer's composing command pointed at it, with the exec's own `--disable` and `-c` items:

    codex app-server --strict-config <--disable ...> <-c ...> --listen stdio://

stdin: `initialize`, `initialized`, `config/read` with `includeLayers` and the clone as `cwd`, held open until the
answer. Exit 0, no stderr. Paths below are replaced: `<job>` is `<runtime>/functional/<job id>`, `<operator-home>` the
operator's home.

## Values

- `default_permissions = 'tester'`, `approval_policy = 'never'`, `sandbox_mode = None`,
  `sandbox_workspace_write = None`, `notify = []`, `model_provider = 'openai'`,
  `web_search = 'disabled'`, `project_root_markers = ['.git']`, `hooks = None`, `mcp_servers = {}`.
- `permissions.tester` is a table: `description`, `extends`, `workspace_roots`, `filesystem.glob_scan_max_depth` and
  the network proxy fields (`allow_local_binding`, `allow_upstream_proxy`, ... `unix_sockets`) are reported as `null`;
  the filesystem entries carry origin `user` (the home's `config.toml`) and `network.enabled = false`.
- `shell_environment_policy`: `inherit = "none"`, `set` the five pinned variables, every other leaf `null`.
- `projects`: one entry, the clone, `trust_level = "untrusted"` (origin `sessionFlags`).
- `skills = {"bundled": {"enabled": false}}`.
- `features`: every disabled feature is reported `false`; features the profile does not disable are reported with
  their own value (some `true`), which the check does not refuse.
