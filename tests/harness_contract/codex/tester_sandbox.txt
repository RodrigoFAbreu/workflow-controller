# Codex tester sandbox, codex-cli 0.163.0 (C10g-1)

Section 1 (CP1): `codex exec --strict-config` and `default_permissions`. Measured 2026-10-27 with no model call
and no spend (exec stops at the stdin prompt, or at the configuration error, before any request). Setup: a scratch
CODEX_HOME holding config.toml, HOME = an empty scratch folder, `-C` a scratch git repo.

| Case | Result |
| --- | --- |
| config.toml: `default_permissions = "tester"` + `[permissions.tester.filesystem]` + `[permissions.tester.network]` | accepted (exec proceeds to read the prompt) |
| `default_permissions = "nosuch"` with only a `tester` table | rejected: `Error: default_permissions refers to undefined profile `nosuch`` |
| `default_permissions = "tester"` with no `[permissions]` table | rejected: `Error: default_permissions requires a `[permissions]` table` |
| the profile name passed by `-c 'default_permissions="tester"'` with the table in config.toml | accepted |
| the same `-c` with an undefined name | rejected (same message as above) |
| `codex mcp list` and `codex features list` with the tester config.toml | run normally ("No MCP servers configured yet."; the feature table) |

Observation: with CODEX_HOME under /tmp, Codex prints `WARNING: proceeding, even though we could not create PATH
aliases: Refusing to create helper binaries under temporary dir "/tmp"`. The Controller's runtime root is never
under /tmp in production; the live tests (CP2) place it elsewhere.

Consequence for the builder: the profile name is written both in config.toml and as a `-c` override
(`required_overrides`), so the argv contract pins it and a later config edit cannot change it. No fallback form is
needed. Whether `codex exec` *applies* the profile (as opposed to accepting it) is settled by the CP2 live run
and recorded in section 2.

Section 2 (CP2): the probes, expected and measured. codex-cli 0.163.0, measured 2026-10-27 with
`CONTROLLER_LIVE_CODEX_TESTS=1 python3 -m unittest tests.test_codex_sandbox_live -v`.

Setup: runtime root under ~/.cache (not /tmp), a `git init` clone with one tracked file, the minimal tester home
(config.toml = `codex_sandbox.config_toml`, private auth.json copy), the stand-in launchers (interpreter
/usr/bin/python3.14 = the resolved sys.executable), a stand-in operator home with a canary file, a canary variable
in the Controller's own environment, a scratch bare origin (an extra read root), a host TCP listener and a host Unix
socket listener. Run (a) `codex sandbox -P tester -C <clone> -c shell_environment_policy... -- sh -c <probe>`
(no model, 0.3 s); run (b) `codex exec --strict-config ... -c default_permissions="tester"` with the probe prompt,
one turn, gpt-6.1-sol (13.6 s). The two runs print the same 18 lines.

| Probe | Expected | Measured (a) and (b) |
| --- | --- | --- |
| tracked (write a tracked file in the clone) | REFUSED | REFUSED |
| git (write .git/config) | REFUSED | REFUSED |
| newfile (create a file in the clone) | REFUSED | REFUSED |
| rename (mv a scratch file over a tracked file) | REFUSED | REFUSED |
| delete (rm a tracked file) | REFUSED | REFUSED |
| scratch (write into the scratch area) | WROTE | WROTE |
| home (write into the stand-in operator home) | REFUSED | REFUSED |
| canary_file (read a file under the stand-in operator home) | BLOCKED | BLOCKED |
| canary_env (read the canary variable) | EMPTY | EMPTY |
| credential (read <codex_home>/auth.json) | BLOCKED | BLOCKED |
| push (git push to the scratch bare origin) | REFUSED | REFUSED; the origin holds no ref |
| gh_name (`gh` by name) | STANDIN | STANDIN (exit 127; the call is in the fake gh log) |
| gh_path (/usr/bin/gh auth status) | FAILED | FAILED |
| tcp (connect to a host TCP listener) | BLOCKED | BLOCKED |
| unix (connect to a host Unix socket) | BLOCKED | BLOCKED |
| tmp, vartmp (write /tmp, /var/tmp) | informational | REFUSED in both runs; the host path is absent |
| sibling (create a file directly in the job folder) | informational | WROTE; the host path is absent |

Host effects, checked after each run: the tracked file is unchanged and `git status` is clean, no new file in the
clone, none in the stand-in home, none in the host /tmp or /var/tmp, the scratch bare origin has no ref, the scratch
file exists, the fake gh log holds the call.

Facts found by measuring, not assumed:
- `codex exec` applies `default_permissions` (it does not merely accept it): the boundaries of (b) match (a).
- A file created directly in an ancestor directory of a listed root (the job folder, the runtime root, the
  operator's home, ~/.cache, ~/Workspace) reports success inside the sandbox but never reaches the host: the
  directory is a private layer. A write below a listed read root, or into a sub-directory that is not listed, is
  refused. That is why `sibling` is informational and the host-absence assertion is the check.
- /tmp and /var/tmp writes were refused (not accepted into a private mount, as the plan expected); informational.
- A model turn may be stopped by Codex's own command guard before the sandbox sees the command: `rm -f` was
  rejected ("rm -f style commands are not permitted"), so the probe deletes with plain `rm`.
- /usr, /etc and the Codex and Controller install trees are readable (the profile lists them); the stand-in `gh`
  only refuses by name, `/usr/bin/gh` is blocked by missing credentials and network, not by the profile.
- `launcher interpreter`: the launchers name the resolved sys.executable.

Limits (KNOWN_LIMITS): composed_configuration only (the tester's composed-configuration check is unbuilt; C10g-3
builds it before the sandbox is wired). Every probe above held on 0.163.0, so none moved to the table.
